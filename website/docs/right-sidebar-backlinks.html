Backlinks

The Backlinks panel lists every note that links to the one you currently have open — the incoming side of the link graph, as opposed to the note's own outgoing links. It's driven entirely by the graph index, so the list updates as soon as another note's link is saved, without you touching the current note at all.

How a backlink gets here

This page is about the panel's own UI — grouping, sorting, and click behavior. For how wiki-links resolve to a target, what the twelve typed-link predicates mean, and how a link gets indexed into the graph as a triple in the first place, see Notes → Links → Backlinks.

Reading the panel

Each row is a source note that links to the current one, with a small notes icon and the source note's title — never its raw file path, though the path is available as the row's tooltip. A header line above the list gives a running total: "N linked mentions". If a note links to the current one more than once (say, via two different typed links), each link is its own row — the count is mentions, not distinct notes.

Filter box
Typing into the ribbon's search field narrows the list to source notes whose title or path contains the query, live as you type. It searches only what's already loaded for the current note — it isn't a project-wide search.
Sort: By type (default)
Rows are grouped into collapsible sections, one per link type, each with a colored square and mono-cased label (e.g. SUPPORTS, REFERENCES) matching that type's color from typed links, plus a count. Click a group header — or its chevron — to collapse or expand it; the ribbon's collapse-all / expand-all buttons act on every group at once.
Sort: Alphabetical
Switching the sort dropdown to "Alphabetical" drops the type grouping entirely and lists every backlink as one flat list, ordered by source note title. Each row instead carries its own small colored badge showing that link's type, since the grouping that would otherwise convey it is gone.
Click a row
Opens the source note in the editor. This is real navigation, not a preview — the current note's own panel state (search text, sort choice, collapsed groups) is left as you had it, ready for when you navigate back.
Drag a row
A backlink row can be picked up and dropped the same way a sidebar file can — useful for dragging a source note into a note body as a new link, or into another drop target that accepts a note reference.

No backlinks

A note with nothing pointing at it shows "No backlinks found" in place of the list — this is expected for a new note, a leaf note, or anything you haven't linked to yet, not an error state. If backlinks exist but your filter text doesn't match any of them, the message changes to "No matches" instead, so you can tell at a glance whether the panel is empty because nothing links here or because your search is too narrow.

Gotchas

  • The panel only knows about the graph, not the disk. A link that hasn't been saved yet — still sitting in an unsaved editor buffer — isn't indexed, so it won't appear as a backlink anywhere until the source note is saved.
  • Same source, multiple rows. If a note links to the current one through more than one typed link, it shows up once per link, not deduplicated into a single row — the mention count in the header reflects this.
  • Collapsed-group state doesn't persist across notes. Switching to a different note resets which type groups are collapsed; it isn't remembered per-note.
