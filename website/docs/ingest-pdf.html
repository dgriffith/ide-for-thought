Docs/Ingest/PDF ingest

PDF ingest

Most PDFs have a text layer Minerva can read directly. The exceptions — scanned pages with no underlying text — get a short, explicit OCR step instead of either failing outright or silently ingesting nothing useful.

Text-layer PDFs

The normal case, whether the PDF came from a local file or a URL: Minerva extracts the text page by page and persists three things under .minerva/sources/<id>/ — original.pdf (the raw bytes), body.md (the extracted text, with a <!-- page N --> marker before each page's content), and meta.ttl (whatever title, author, and date the PDF's own /Info dictionary provided).

Scanned PDFs — the OCR handoff

When a PDF has no text layer, Minerva still saves original.pdf and a stub meta.ttl, but body.md stays empty until you complete OCR. The app detects this and hands off to an in-app OCR pass — Tesseract.js, running right in the renderer, no external service — which you confirm before it runs.

If you run OCR
Each page is recognized and the result becomes body.md, with thought:extractionMethod stamped "ocr" on the source (as opposed to "text-layer" for the normal case) — so you can tell later which sources came through which path.
If you skip it
The source stays on disk with original.pdf and its metadata intact — you can open the source later and run OCR then. Nothing is lost by skipping; the body is just a placeholder until you do.

Two things worth knowing up front

Encrypted PDFs are rejected with a clean error rather than ingesting a broken source — decrypt it first if you need it in your thoughtbase. And a PDF's source id is always a content hash, never a DOI pulled from the file, even when the PDF's metadata has one — PDFs rarely embed a DOI reliably enough to key on, so the id is based on the file's own bytes instead. See Citing & duplicates for what this means if the same paper also arrives later via its DOI or arXiv id.
