Math

Minerva renders LaTeX math wherever it appears in a note — inline in a sentence or as its own centered display equation — using the same $…$ / $$…$$ convention as Pandoc and most markdown-flavored notes apps. Rendering happens through KaTeX, so it's fast and works offline: no server round-trip, no network dependency.

Syntax

Wrap LaTeX in single dollar signs for inline math, doubled dollar signs for a block display equation.

$…$
Inline. Renders in place, mid-sentence. Example: the update rule is $\theta_{t+1} = \theta_t - \eta \nabla L(\theta_t)$.
$$…$$
Block. Renders as its own centered display equation. Example: $$\int_0^\infty e^{-x^2}\,dx = \frac{\sqrt{\pi}}{2}$$

A block equation can open and close on one line, or span several — the closing $$ just needs to end its own line:

$$
P(A \mid B) = \frac{P(B \mid A)\,P(A)}{P(B)}
$$

How math renders

Inline math renders directly in the flow of text at normal size. Block math renders inside a bordered card — the same visual treatment as a code block — with the equation centered and the card scrolling horizontally if the equation is too wide to fit.

A $$…$$ pair written mid-paragraph (not at the start of a line) still renders in display mode, just without its own card — useful for a one-off large equation you don't want to break out of the sentence.

Malformed LaTeX doesn't break the preview

An equation KaTeX can't parse renders as an inline error span showing the raw source, rather than failing the whole note's preview. Hovering the error span shows KaTeX's parse error as a tooltip, so you can see exactly what's wrong without leaving the note.

Gotchas

  • Unsupported LaTeX commands. Minerva renders whatever KaTeX supports — a large but not complete subset of LaTeX math. A command from a package KaTeX doesn't implement will render as the error span described above rather than being silently dropped.
  • No space right after the opening $ or before the closing $. This is intentional, so ordinary prose mentioning money — "cost: $5 today, $50 tomorrow" — doesn't get swept into a math span. $x+1$ is math; $ x+1 $ is not. Digits right after the opening $ are fine ($0.6<z<4$ works), just not whitespace.
  • No blank line inside inline math. An unescaped line break inside a $…$ span ends the match instead of continuing it — keep inline math on one line. Block $$…$$ math is fine spanning multiple lines.
  • Escaping a literal dollar sign. Write \$ to show a literal dollar sign next to math-like content without triggering inline math.
  • Math inside code fences and inline code is left alone. A $…$ written inside a fenced code block or inline `code` span is shown as literal text, never rendered as math.
  • Table cells render math normally. A markdown table cell goes through the same inline-rendering pipeline as body text, so $…$ works unescaped inside a cell — no special escaping needed beyond the rules above.
  • Note frontmatter is not rendered as markdown. The YAML frontmatter block is stripped out before the note body is rendered, so $…$ in a frontmatter value is shown as plain text in the frontmatter panel, not as math. (The Source viewer's title and abstract fields are the exception — see Frontmatter for where properties do and don't get markdown treatment.)
