Tables & CSV

Markdown tables render the way you'd expect — a header row, an alignment row, and as many data rows as you like. What's less obvious is that every table in a note is also read as data: on each save, Minerva parses its rows and columns into the knowledge graph using CSVW, the W3C vocabulary for describing tabular data. You don't opt in — a table is always both a formatted block in your text and a small dataset in the graph.

Syntax

Minerva uses standard GFM (GitHub-Flavored Markdown) pipe tables. A leading and trailing | on each row is conventional but not load-bearing for rendering — what matters is the separator row between the header and the data.

| A | B |
Header row. One line, cells separated by |. Becomes the column names for both rendering and graph extraction.
|---|---|
Separator row. Required immediately after the header. Marks where the header ends and data begins — without it, the lines above and below are just a paragraph, not a table.
:---
Left-align the column (also the default with no colon).
---:
Right-align the column — handy for numeric data.
:---:
Center-align the column.
| a \| b |
Escaped pipe. A backslash before a pipe inside a cell renders it as a literal | instead of a column break.

A short example:

| Trial | Condition | Effect size |
|:------|:---------:|------------:|
| 1     | control   |        0.12 |
| 2     | treatment |        0.61 |
| 3     | treatment |        0.58 |
📊
Screenshot — Rendered table in preview
The rendered preview of the trial/condition/effect-size table above: a bordered table with a bold header row, the first column left-aligned, the second column centered, and the numeric third column right-aligned.

Rendering is unmodified GFM — the same table syntax you'd write for GitHub. There's no support for merged or spanned cells (no colspan/rowspan); each cell is exactly one row by one column.

How tables become CSVW

On every index pass, Minerva walks each note's parsed tables and writes them into .minerva/graph.ttl using CSVW — the real W3C namespace, not a Minerva-specific one. Each table becomes a csvw:Table linked to its note with csvw:inNote; each header becomes a csvw:Column with a csvw:name and csvw:columnIndex; each data row becomes a csvw:Row; and each row/column intersection becomes a csvw:Cell carrying the cell's value. csvw is one of the prefixes auto-injected into every query, so you can reach this data from Graph > Query without declaring the namespace yourself.

Every table, no opt-in

There's no caption, id, or frontmatter flag that marks a table as "graph-worthy." Any syntactically valid table — header row, separator row, at least one data row — is extracted automatically. A table with a header and separator but zero data rows is the one exception: it's dropped silently, both from rendering as a meaningful table and from the graph. There's no way to write a markdown table that's decorative-only and keep it out of the graph; if you don't want tabular content indexed, it can't be a markdown table.

Gotchas

  • Alignment is display-only. The :--- / ---: / :---: markers control text alignment in preview and nowhere else — that information isn't captured when a table is extracted into the graph. A SPARQL query over a table's cells can't tell you which columns were right-aligned.
  • Escaped pipes render correctly but don't extract correctly. Preview handles \| as a literal pipe character inside a cell. The graph indexer's table parser doesn't — it splits naively on every |, so a cell written as a \| b shows up as one cell in preview but as extra, misaligned cells in the CSVW triples. Avoid literal pipes in cell content if you plan to query that table.
  • Tables inside code fences aren't extracted. A pipe table written as an example inside a fenced code block renders as code, not a table, and is correctly excluded from graph indexing.
  • This isn't the CSV/DuckDB pipeline. The right sidebar's Tables panel lists tables referenced by ```sql fences and registered .csv files in your project — a separate, SQL-oriented feature. It doesn't show markdown tables or CSVW data. The only way to see a markdown table's extracted triples today is a graph query.
