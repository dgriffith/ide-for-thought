Diagrams

A mermaid fence renders as a live diagram wherever it appears in a note — flowcharts, sequence diagrams, and anything else Mermaid's own syntax supports. Minerva doesn't restrict which Mermaid diagram types you can draw; it hands your fence content straight to the Mermaid library and draws whatever comes back as inline SVG, recolored to match the note around it.

The mermaid fence

A diagram is a fenced code block whose language is mermaid. Everything inside the fence is Mermaid's own diagram-definition language — Minerva doesn't parse or validate it beyond handing it to the renderer.

```mermaid
flowchart LR
  A[Draft] --> B{Reviewed?}
  B -- yes --> C[Published]
  B -- no --> A
```

To insert one, right-click in the editor and choose Elements → Mermaid Diagram — it drops an empty fence with the cursor inside, ready for a diagram definition.

Diagram types

The fence renderer (renderMermaidFence in Preview.svelte) does no type-checking on the content — it escapes the fence body and hands it to Mermaid's render() call as-is, in mermaid-renderer.ts. That means any diagram type Mermaid itself understands works in a Minerva note: flowcharts, sequence diagrams, class diagrams, state diagrams, ER diagrams, Gantt charts, and the rest of Mermaid's grammar. Two of the most common are worth a quick reference:

flowchart
Flowchart. Nodes and directional edges — LR (left-to-right), TD (top-down), and the other Mermaid layout directions all work. 
```mermaid
flowchart TD
  Start --> Decision{OK?}
  Decision -->|yes| End
  Decision -->|no| Start
```
sequenceDiagram
Sequence diagram. Participants and the messages passed between them, in order. 
```mermaid
sequenceDiagram
  Alice->>Bob: Question
  Bob-->>Alice: Answer
```

How it renders

In preview, the fence becomes a bordered block with a collapse toggle in its toolbar — the same convention as other fence types — and the diagram itself renders as inline SVG below it. Rendering is lazy: Minerva dynamic-imports the Mermaid library the first time a diagram needs drawing, rather than bundling it into the app's startup path.

Theme colors carry into the diagram

Minerva initializes Mermaid on the base theme and overrides its variables with the app's own Catppuccin tokens — background, text, borders, node fill, and accent all come from the same CSS custom properties the rest of the note uses. Switch Minerva's theme (dark, light, or contrast) and diagrams redraw to match; there's no separate diagram theme to configure.

Gotchas

  • A syntax error renders inline, not as raw text. If Mermaid can't parse the fence content, the block shows a small "Mermaid error" panel with the underlying error message in place of the diagram — the rest of the note keeps rendering normally. Fix the definition and the diagram appears in its place.
  • Re-rendering is idempotent. A diagram block is marked once it's rendered, so re-running the preview's hydration pass (for example after an unrelated edit elsewhere in the note) doesn't redraw diagrams that already succeeded.
  • No live player, no external calls. Rendering happens entirely locally through the bundled Mermaid library — nothing about a diagram's content is sent anywhere.
