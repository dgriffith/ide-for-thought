Docs/Viewing options/View modes

View modes

Every open note has a view mode: raw markdown in the editor, the rendered read-only page, or both side by side. It's a per-pane setting — a split pane can show one note in Source while another shows a different note in Preview — and switching modes never touches the file on disk, so it's a free, reversible way to look at the same content differently.

The three modes

The mode lives on the pane (called a "group" internally), not on the note itself — reopen a note later and it comes back in whatever mode that pane was last set to, not whatever mode it was in when you closed it (src/renderer/lib/stores/editor.svelte.ts:576 — setViewMode(mode, groupId) sets it per group).

Source
The raw .md text in the CodeMirror editor — what you'll want for anything mechanical: fixing a wiki-link, editing frontmatter, working inside a code fence. Labeled Source on the toolbar.
Preview
The fully rendered, read-only page — headings, callouts, math, diagrams, charts, and embedded media all render live. Labeled Preview on the toolbar.
Editor + Preview
Source on the left, rendered Preview on the right, in the same pane. Internally this is the editor-preview mode; the toolbar calls it Side by side.

These three are exactly the values of the ViewMode union — 'source' | 'preview' | 'editor-preview' (src/renderer/lib/stores/editor.svelte.ts:92). A plain-text file (no markdown rendering — see Notes) skips the toggle entirely and only shows Source, since a Preview of plain text would just be an empty pane.

Switching modes

Two ways to change a pane's mode, both acting on the same underlying editor.setViewMode() / editor.cycleViewMode() calls:

Toolbar buttons
Three buttons above the note — Source, Side by side, Preview — jump straight to that mode regardless of what it's currently showing. Each calls editor.setViewMode('source' | 'editor-preview' | 'preview', groupId) directly (src/renderer/App.svelte:1360-1372); there's no cycling involved, so you can go from Source straight to Preview without passing through the split view.
Cycle shortcut — ⌘⇧P
Steps the active pane through the three modes in order: Source → Preview → Editor + Preview → Source (cycleViewMode(), src/renderer/lib/stores/editor.svelte.ts:580-585). Bound globally as CmdShiftP / CtrlShiftP (src/renderer/lib/keymap/handle-keydown.ts:52-55) and also reachable from the View menu as Cycle Preview Mode (src/main/menu.ts:428-432).
Why ⌘P was taken already

Minerva binds ⌘P to Quick switch rather than a preview toggle, unlike some other markdown editors — so the cycle shortcut adds ⇧ instead. See Command palette for the related ⌘K binding.

Gotchas

  • No scroll sync in Side by side. The source and preview panes scroll independently — scrolling one does not move the other. Each pane just remembers its own scroll position for restoring the note later (src/renderer/lib/components/Editor.svelte:932-933); they aren't linked to each other.
  • Cursor and scroll position survive a mode switch. Toggling between Source, Preview, and Side by side doesn't remount the editor — it's only swapping which pane(s) are visible around it — so your cursor offset and scroll position in the source editor are exactly where you left them when you switch back to Source.
  • The mode belongs to the pane, not the note. Split your window into two panes, put one in Preview and one in Source, and that assignment sticks per pane even as you switch which note is open in it.
  • Plain-text files have no toggle. A file that Minerva treats as plain text (not markdown) has nothing to render, so the Source/Side by side/Preview toolbar doesn't appear for it at all — you're always in Source for those.
