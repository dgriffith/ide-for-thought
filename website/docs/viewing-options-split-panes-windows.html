Split panes & windows

A single tab strip is fine until you want to see two notes at once — a source next to the claim it supports, or an outline next to the section you're drafting from it. Minerva gives you two ways to do that: split the current window into multiple panes, each with its own tabs and its own view mode; or open an entirely separate window. They solve different problems, and knowing which one you want saves a few seconds of fighting the layout.

Panes and groups

Internally, a pane is called a group — an independent unit owning its own tab strip, active tab, and view mode (EditorGroup, src/renderer/lib/stores/editor.svelte.ts:100-105). A window with no splits is just one group. The panes themselves are arranged in a recursive layout tree of horizontal/vertical splits with fractional sizes, so you can split a pane that's already inside a split (LayoutNode, src/renderer/lib/editor/layout-tree.ts:12-27); dragging the hairline between two panes resizes just that pair.

Split right
⌘\ (Ctrl\ on Windows/Linux), the split-pane icon button in a pane's toolbar, or View → Split Editor Right. Splits the focused pane horizontally, adding a new empty pane to its right and focusing it (editor.splitGroup(groupId, 'horizontal'), src/renderer/lib/stores/editor.svelte.ts:253-262).
Split down
⌘⇧\ (CtrlShift\), the toolbar's split-down button, or View → Split Editor Down. Same as Split Right but stacks the new pane vertically, below the focused one.
Drag a tab to an edge
Press and drag a tab toward the left, right, top, or bottom edge of any pane; a preview shows where it'll land. Dropping on an edge band splits that pane along the matching axis and moves the tab into the new sub-pane — dragging to the left or right edge splits horizontally, top or bottom splits vertically (dropZoneFromFraction / splitForZone, src/renderer/lib/editor/drop-zone.ts:13-46).
Focus next / previous pane
⌘⌥→ / ⌘⌥← (CtrlAlt), or View → Focus Next/Previous Group. Cycles focus through panes in left-to-right visual order, wrapping at the ends.
Close pane
⌘⇧W or View → Close Group. Closes every tab in the focused pane and collapses it out of the layout tree, rebalancing the remaining split.

Moving tabs between panes

Once you have more than one pane, a tab can move between them two ways:

Drag to center
Drag a tab and drop it in the middle of another pane (including onto its tab bar) rather than on an edge — this moves the tab into that pane without creating a new split, the same "move here" gesture VS Code uses.
Move to Other Group
Right-click a tab for its context menu. With exactly one other pane open it's a single-click Move to Other Group; with more than two panes it expands into a submenu listing each by position (Group 1, Group 2, …) so you can pick the destination (TabBar.svelte:174-180).

A file, source, or PDF can only be open in one pane at a time — Minerva won't let you open the same note twice into two panes as separate buffers, since that would race two copies against each other on save. Trying to open something that's already open elsewhere just refocuses the pane it's already in.

Each pane keeps its own view mode

View mode — Source, Preview, or Editor + Preview — lives on the group, not on the note or the window. Split a pane and the new one inherits the splitting pane's mode so the split feels continuous, but from that point the two are independent: switch one pane to Preview and the other stays in Source, and each remembers its own mode as you switch which note is open in it.

Opening a new window

File → New Window (⌘⇧N) opens a second, completely blank Minerva window with no project loaded — you then open a thoughtbase into it the same way you would the first window. It is not tied to whatever project is open in the window you triggered it from.

Same project, or a different one — your choice

A new window can open the same thoughtbase as another open window, or a completely different one. When two windows point at the same project's root path, Minerva shares one underlying project context between them — the graph, search index, tables, and embeddings are initialized once and reference-counted across acquiring windows, not duplicated (acquireProject, src/main/project-context.ts:52-96). A note saved in one window is written to disk and re-indexed once; the other window's file watcher picks up the change and reflects it, same as if the file had changed from outside the app.

Split pane or new window?

Both let you look at two things at once — the difference is scope and independence:

Prefer a split
You're working within one project and want two views alongside each other on one screen — a source next to the note citing it, an outline next to a draft, or the same note in Source and Preview. Panes share the window's size, menu, and focus.
Prefer a new window
You want a second, independently movable and resizable surface — across two monitors, for example — or you want to have two different projects open at once. A window is also the only way to get a fully separate set of panes: splitting only subdivides the window you're already in.

Gotchas

  • Closing a pane's last tab collapses the pane. Close every tab in a split pane (one at a time, or via Close All) and the now-empty pane collapses out of the layout tree automatically, handing its space back to its sibling — you don't end up staring at a blank pane. The one exception is a window with a single pane and no split: that one stays, showing its normal empty "no file open" state, since a window always keeps at least one pane.
  • A new window starts blank, not cloned. New Window never copies the current window's open tabs, panes, or project — it's a fresh window exactly like the one you'd get from launching the app again. If you want the same project open a second time, you open it again from the new window's File menu (or Recent Thoughtbases).
  • Same project across windows means shared state, not synced UI. The graph and indexes are shared and stay consistent, but each window's panes, tabs, and view modes are independent — closing a pane in one window has no effect on the other.
  • Drag vs. click targets differ by pixel region. The edge bands that trigger a split are the outer quarter of a pane on each side; the inner half plus the entire tab bar is the "move without splitting" zone. If a drag keeps splitting when you meant to move a tab into a pane, drop closer to its center or onto its tab bar instead.
