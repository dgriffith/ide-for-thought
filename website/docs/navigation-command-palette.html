Command palette

The command palette is Minerva's do-anything launcher. Press ⌘K (or CtrlK on Windows/Linux) from anywhere in the app, type a few letters, and press ↵ to run the highlighted command. It searches commands and actions only — for jumping to a note, source, or query by name, see Quick switch instead.

Opening the palette

The shortcut is registered in the global keymap as ⌘K / CtrlK, with no ⇧ or ⌥ modifier (src/renderer/lib/keymap/handle-keydown.ts:37). Minerva follows the Linear / VS Code convention rather than Obsidian's: ⌘⇧P was already taken elsewhere in the app, and ⌘P is reserved for Quick switch rather than the command palette.

No dimmed backdrop

Unlike most command palettes, Minerva's doesn't dim or block the editor behind it — this is by design. The palette floats over your note without obscuring it, so you can still see what you're about to act on while you type.

Empty query

Open the palette with nothing typed and it lists every command in the registry — File, Edit, View, Navigate, Refactor, Research, Query, and App actions alike. Ordering is deliberate, not alphabetical throughout:

Recently used
Commands you've run before appear first, most-recent first. A thin divider line separates this block from the rest — there's no category header, just the divider.
Everything else
The remaining commands follow, sorted alphabetically by title.

Typed query — fuzzy ranking

As you type, every command is scored against the query and re-sorted. Matches against the command's title or category both count, but title matches rank higher. Roughly, from strongest to weakest match:

Substring in title
The query appears anywhere in the command's title — the strongest signal.
First letters of words
The query matches the first letter of each word in the title, e.g. nn for "New Note".
camelCase prefix
The query matches a prefix formed from capitalized-word boundaries in the title.
Substring in category
The query doesn't match the title, but does match the command's category (e.g. "Refactor", "Query").
Fuzzy title / fuzzy category
The weakest tier: the query's characters appear in order somewhere in the title (or, weaker still, the category) without being contiguous.

A command you've run recently gets a small bonus on top of its match score, and ties are broken alphabetically by title — so two equally-good matches always land in a stable, predictable order.

Screenshot — Command palette with a typed query
The command palette open over a note, with "link" typed into the search field and a ranked list of matching commands below it — each row showing the command title, its category in small muted text, and a keybinding right-aligned where one is bound; the top result is highlighted as the current selection.

If nothing matches, the palette shows No commands match "your query" in place of the results list — there's no partial-match fallback or suggestion.

Keyboard navigation

↑ ↓
Move the selection up or down through the results, clamped at the top and bottom of the list. Moving the mouse over a row also updates the selection.
↵
Run the selected command. The palette closes first, then the command runs — so focus returns to the editor immediately rather than waiting on the command to finish.
esc
Close the palette without running anything.

The palette's footer states this literally: ↑↓ navigate · ↵ run · esc close.

Gotchas

  • Commands only — never notes, sources, or queries. The palette's candidate set is built entirely from the app's command registry (File, Edit, View, Navigate, Refactor, Research, Query, App). It never searches your notes, sources, or saved queries by title or content. If you're trying to jump to a note, open Quick switch (⌘P) instead.
  • Disabled commands still show up. A command that isn't currently applicable (for example, an action that needs an active selection) still appears in the list, greyed out. It just can't be clicked or run until its precondition is met — the palette doesn't hide it.
  • No dimmed backdrop. The editor stays fully visible and undimmed behind the palette; don't mistake this for a bug if you're used to a modal overlay from other apps.
  • Recent history is local and capped. The last 10 run commands are remembered (in localStorage) to drive the recent-first empty-query ordering. It's per-machine, not synced with the project.
