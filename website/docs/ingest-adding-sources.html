Adding sources

There's more than one door in, depending on what you're starting from: a URL, an identifier, a file already on disk, or a whole reference library you want to bring over at once.

The File menu

Five dedicated actions, each doing one thing well rather than one smart button trying to guess:

Ingest URL as Source…
Cmd+Shift+I
Prompts for a URL and runs it through Readability extraction. URL only — it won't recognize an identifier typed into this prompt.
Ingest Identifier…
Cmd+Shift+D
Prompts for a DOI, arXiv id, or PubMed id and looks it up against CrossRef / arXiv / PubMed. Also tries to fetch an open-access PDF automatically when one exists — if that specific fetch fails, the source still ingests fine with its metadata; the source's bibo:uri points at the canonical record so you can grab the PDF by hand.
Ingest File as Source…
Opens a native file picker (not a drop target) for a local PDF, HTML, or plain-text/markdown file.
Import BibTeX…
Bulk-imports a .bib file. Reports imported / duplicate (skipped) / failed / parse-error counts when it finishes.
Import Zotero RDF…
Bulk-imports a Zotero RDF export, lifting any attached PDFs along with each entry's metadata.

The Sources panel's + button

The quickest path for a one-off: click + in the Sources panel and paste in a URL, DOI, arXiv id, or PubMed id. Unlike the menu's URL/Identifier actions, this one smart-routes — it recognizes which kind of thing you pasted and picks the right path automatically. It also catches a DOI embedded in a longer piece of pasted text (e.g. "see 10.1145/xxxx for details"), extracting just the identifier rather than failing on the surrounding prose.

Drag and drop

Dropping files onto the Notes tree isn't source-specific — it's a general "bring this file into the project" gesture that branches by file type:

.pdf
Ingested as a Source, the same as the menu's PDF path. The folder you dropped onto is ignored — sources live in the sources library, not the file tree.
.md / .ttl / .csv
Copied into the thoughtbase as a regular file, at the folder you dropped onto — not ingested as a Source. A name collision gets auto-renamed (foo.md, foo-2.md, …) rather than overwriting.
Anything else
Rejected, with a reason shown for each skipped file. One unsupported file in a multi-file drop doesn't cancel the rest of the import.
Why re-adding the same paper doesn't duplicate it

Every source is stored under an id derived from its most stable identifier — DOI, arXiv id, PubMed id, ISBN, or (falling back) a hash of its URL or content. Ingesting the same paper twice by the same route produces the same id, so a duplicate is just a no-op. See Citing & duplicates for what happens when the same paper arrives via different identifiers.

Gotchas

  • The menu's "Ingest URL" and "Ingest Identifier" don't smart-route — the Sources panel's + button does. Paste a DOI into the URL prompt and it fails; paste it into the + button and it works. If you're not sure which kind of thing you're holding, use the + button.
  • PDF ingest doesn't key off a DOI even when one's findable. A PDF's source id is always a content hash, not a DOI extracted from the file — see PDF ingest for why, and Citing & duplicates for the merge step this can require.
  • Bulk imports report failures inline, not silently. A BibTeX or Zotero RDF import that partially fails still completes the entries it can, then shows you the first few failures with a reason — check the summary rather than assuming a clean run.
