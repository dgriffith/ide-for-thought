Managing & authoring

Every skill — stock or your own — can be turned off, moved to a different menu, or reordered from Settings → Skills. The changes are per-machine, take effect immediately, and never require editing a file by hand.

Managing skills from Settings

Open Settings → Skills and each of the three menus — Learning, Research, Analysis — lists its skills as rows, stock and user skills together. Every row carries an enable checkbox, up/down reorder buttons, and a menu dropdown, so the whole surface is a working control panel, not a JSON file you're expected to open in an editor.

Enable / disable
The checkbox on each row hides a skill from every surface — menu, command palette, and slash commands — without deleting its file. Stock skills can't be removed outright, so this is how you turn one off; a disabled row stays visible in Settings (dimmed) so you can find it again later.
Reassign to a different menu
The dropdown on each row moves that skill into a different one of the three fixed menus, overriding whatever menu the skill's own frontmatter declares. Useful when a skill you use constantly is buried in Analysis but you'd rather reach it from Learning.
Reorder within a menu
The ↑ / ↓ buttons move a skill up or down within its current menu's list. Order here is the order it appears in the actual menu, the command palette, and the slash-command list.

Where this lives on disk

These per-machine overrides are persisted to ~/.minerva/menu-config.json. You never need to open that file — Settings is a full read/write interface for it — but if you're curious, it's a small JSON object mapping skill IDs to an enabled flag and a menu override, plus an explicit ordering array per menu. A skill with no entry there is enabled, in its declared menu, and sorted after any explicitly-ordered skills, so a fresh install needs no config file at all and newly added skills just slot in.

Gotchas

  • Changes apply immediately — no restart. Toggling, reassigning, or reordering a skill updates the menu bar, the command palette, and the slash-command list right away. The Settings panel writes optimistically (the UI reflects the change before the save round-trip finishes), so the effect is visible before you've even closed the dialog.
  • It's per-machine, not per-project. menu-config.json lives under your home directory, not inside a project's .minerva/ folder — so the same overrides follow you across every thoughtbase you open on that machine, but don't travel with the project itself if you open it on another computer.
  • A bad hand-edit degrades quietly, not fatally. If you do go poking at the file directly and leave it malformed, Minerva drops whatever it can't parse and falls back to defaults for the rest rather than failing to start — but there's no reason to hand-edit it when Settings does the same job with immediate visual feedback.

Ready to write your own skill instead of just rearranging the stock ones? The full authoring reference — frontmatter fields, the template language, tool wiring, and a worked example — lives at docs/authoring-skills.md in the repo. This page won't duplicate it; start there.
