Callouts & cards

A callout turns an ordinary blockquote into a titled, colored box — a note, a tip, a warning-equivalent, a flashcard. The syntax is Obsidian's [!type] convention: a blockquote whose first line names a kind. Minerva also accepts a lenient bare form with no leading >, and one kind — card — renders as a front/back flashcard instead of a plain note box.

Syntax

A callout's marker line is [!type], optionally followed by + or - to make it collapsible, and an optional custom title. Everything after the marker line — inside the blockquote — is the callout body.

> [!type]
Standard form. A blockquote whose first line is [!type]. Every following >-prefixed line is the body. This is the same syntax Obsidian and GitHub use.
[!type]
Bare form (lenient extension). A top-level paragraph starting with [!type] becomes a callout even without the leading >. It always renders non-collapsible — there's no blockquote container to attach a disclosure to. Only fires at the top level; a [!type] line nested inside a list or another blockquote is left alone.
> [!type]+
Collapsible, default-expanded. Renders as a <details open>/<summary> pair instead of a plain <div>, so it's keyboard-operable and starts open.
> [!type]-
Collapsible, default-collapsed. Same as above but starts closed — the body is hidden until clicked.
> [!type] Custom title
Custom title. Text after the marker (and fold flag) replaces the kind's default title in the title bar. Whitespace here is restricted to spaces/tabs, so a title can't accidentally swallow the body's first line.

A complete example, plus the bare form:

> [!warning] Before you continue
> This rewrites every note's frontmatter in place. Commit first.

> [!tip]-
> Collapsed by default — click to expand.

[!note]
No leading > required — this still becomes a callout.

Supported kinds

Fourteen kinds are recognized by name; each has a default icon, a default title (used when you don't supply a custom one), and a color drawn from the existing palette — nothing new, no red/danger styling. An unrecognized kind (e.g. [!random]) still renders as a callout: it falls back to a generic dot icon and the accent color, with the kind name capitalized as its title.

note
Default title "Note". Accent-colored.
info
Default title "Info". Iris-colored.
tip
Default title "Tip". Sage-colored.
success
Default title "Success". Sage-colored, checkmark icon.
question
Default title "Question". Accent-colored, "?" icon.
warning
Default title "Warning". The warmest tone in the set (an amber/rust shade, not red) with a triangle icon — Minerva's stand-in for danger styling.
failure
Default title "Failure". Same warm tone as warning, "✗" icon.
danger
Default title "Danger". Same warm tone as warning — Minerva has no separate red danger color, per house style.
bug
Default title "Bug". Iris-colored.
example
Default title "Example". Iris-colored.
quote
Default title "Quote". Muted-text colored rather than an accent — reads as a citation, not an alert.
abstract
Default title "Abstract". Iris-colored.
todo
Default title "Todo". Accent-colored, checkbox icon.
card
Default title "Card". Renders as a flashcard rather than a plain note box — see below.

Card-style callouts

[!card] is syntactically an ordinary callout — same marker, same blockquote body — but it's treated differently once inside: an <hr> (a --- line) in the body splits it into a front and a back, the way a flashcard's prompt and answer are two separate things. Minerva's preview hydrates this after render by moving everything after the divider into a collapsed Show answer disclosure, so the front stands alone until you choose to reveal the back — the divider itself is replaced by the disclosure's summary line.

A card without a --- divider is left untouched — it just renders as a front with no answer to reveal, same as a malformed or front-only card.

A card's title line also has one more piece of machinery: a trailing ^id block-id (used to anchor the card for spaced-repetition review) is stripped from the displayed title, leaving only the deck name you wrote — or the default "Card" title if the marker line held nothing but an id.

> [!card] Biology deck
> What organelle produces most of a cell's ATP?
> ---
> The mitochondrion.
Unrecognized kinds still work

A kind that isn't in the built-in list doesn't fail to render — it becomes a callout styled with the accent color and a generic dot icon, titled with the capitalized kind name (or your custom title, if you supplied one). This makes ad hoc kinds safe to use for personal conventions.

Nesting and nuances

  • Nesting works for free. A callout inside a callout is just a nested blockquote — Minerva's core render rule walks every blockquote_open token independently, so nested callouts need no special-case syntax.
  • Bare callouts can't collapse. Because the lenient no-> form has no blockquote container, +/- fold flags on a bare [!type] line are meaningless — collapsibility requires the standard blockquote form.
  • Kind names are case-insensitive. [!Warning] and [!warning] resolve to the same kind; the stored kind is always lowercased.
  • Collapsible callouts render as <details>. That means keyboard operability (focus, Enter/Space to toggle) comes from the browser, not from custom script.
