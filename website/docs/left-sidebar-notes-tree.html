Notes tree

The Notes tab is the left sidebar's default panel — the file/folder tree that mirrors your project's directory structure on disk. This page covers the panel itself as a piece of UI: the header controls, how the tree displays folders and files, and how creating, renaming, and moving notes are exposed here specifically. For the underlying concepts — what a note is, the full lifecycle, everything you can embed in one — see Notes.

The panel header

Above the tree sits a header with the panel title and a count on the right, then a row of three small tool buttons once the project has at least one note:

Note count
A plain number next to the "Notes" title — no icon, no label, just a tabular-numeral count. It's a recursive file count, not a top-level one: every file anywhere in the tree, folders excluded, counted depth-first. It's a derived value, so it updates live the instant a note is created, deleted, or moved — there's no separate refresh step.
Expand all / Collapse all
Two toolbar buttons above the tree. Expand All opens every folder in the project at once, regardless of current state; Collapse All folds everything shut. Both act on the whole tree, not just the visible portion.
Auto-reveal active file
A toggle button (pressed = on) that keeps the tree in sync with whatever note is open in the editor: switching files expands every ancestor folder and scrolls the row into view automatically. It only reveals — clicking a folder to open or close it never re-triggers a reveal, so manually browsing the tree doesn't fight with whatever you have open elsewhere.
The project name is a row, not a header

If the sidebar has a project name to show, it renders as a synthetic root row above the real tree — with its own folder icon and disclosure arrow — rather than as a section heading. It behaves like any other folder row (click to expand/collapse) but sits outside the multi-selection and drag-and-drop model, so it can't be accidentally selected, deleted, or dragged.

Reading the tree

Folders and files are interleaved in a single hierarchical list, indented by depth. A few things about how it's populated and displayed are worth knowing:

Empty folders
Shown, not filtered out. An empty folder is a normal, visible row you can expand (to see nothing) or drop a file into — Minerva doesn't hide directories just because they're currently empty.
Every file type
The tree lists every file in the project, not just .md notes — .csv tables, .ttl Turtle/RDF, .py compute cells, and plain-text or code files each get a distinct row icon. Anything else falls back to the default note-page icon, since a curated notebase is almost always markdown-adjacent rather than an arbitrary binary.
Modified time
File rows show a relative timestamp ("3h ago") on the right when the file has a known modification time. Folder rows don't carry one.
Expand / collapse
Only the disclosure chevron toggles a folder open or shut. Clicking the rest of the row selects the folder without touching its expanded state — so you can select a folder (to delete it, tag it, and so on) without it springing open or shut underneath you.
Keyboard navigation
Click the tree (or Tab into it) to give it keyboard focus, then ↑/↓ move a cursor through the currently visible rows — respecting collapsed folders — without opening anything. Enter opens the focused file or toggles the focused folder. ⌘↓/⌘↑ expand/collapse the focused folder in place. Space toggles the focused row into/out of the selection. ⌘A selects every visible row; Esc clears the selection.
Multi-select
⌘-click toggles a row in or out of the selection without opening it; Shift-click selects a contiguous range in visible order. A selection-count badge ("3 of 42 selected") appears above the tree once anything beyond a single row is selected, with a "clear" link. Right-clicking a row that's already part of the selection keeps the whole selection intact — so Delete or a tag action from the context menu applies to everything selected, not just the row you clicked.

Creating notes and folders from the panel

Right-clicking empty space in the tree (or the project-root row) opens a menu with just two entries: New Note and New Folder. Right-clicking an existing folder gets the same two entries at the top, scoped to create inside that folder rather than at the project root. New Note here opens the same naming dialog described in Notes → The note lifecycle; New Folder is the sidebar-specific counterpart — there's no File-menu or command-palette equivalent for creating a folder, only this context menu.

Renaming and moving

Right-clicking a note or folder opens a fuller context menu: Cut, Copy, Paste (when something's on the clipboard), New Note, New Folder, then a separator before Rename, Merge into… (notes only), Copy Path, Bookmark and Toggle Entrypoint (notes only), an Open In submenu (Reveal in Finder / Open in Default App / Open in Terminal), Add Tag…, Remove Tag…, Format, and finally Delete.

Rename
Context menu → Rename. Same prompt-with-prefilled-name behavior as described in the note lifecycle — wiki-links elsewhere in the project are rewritten to match.
Move (drag)
Every row is natively draggable. Drag a file or folder onto a target folder row to move it there; drop on empty space below the tree (or on the root row) to move it to the project root. Dropping a file straight into the editor — rather than onto a folder — inserts a resolving wiki-link instead of moving it; that's a different drag payload from a folder-to-folder move.
Move (Cut / Paste)
Context menu → Cut on the source, then Paste on the destination folder's context menu. Functionally the same move as dragging, useful when the source and destination aren't both scrolled into view at once.
Copy
Context menu → Copy, then Paste elsewhere — duplicates rather than moves.
External drops
Dragging files in from Finder (or another app) onto the tree imports them into the project at the drop location, rather than being treated as an internal move.

Deleting is a plain confirmation, not a warning

Delete from this menu follows the same rule as everywhere else in Minerva: no red styling, just a plain "Delete note "name"?" confirmation with a "don't ask again" option, backed by the fact that git has your history regardless. See Notes → The note lifecycle for the link-check Minerva runs first.

No notes yet

A brand-new project with zero files shows a plain "No notes yet" message in place of the tree — the toolbar (Expand All / Collapse All / Auto-reveal) doesn't render at all until there's at least one file, since there's nothing yet for those controls to act on. Right-clicking the empty state still opens the New Note / New Folder menu, so an empty project isn't a dead end.
