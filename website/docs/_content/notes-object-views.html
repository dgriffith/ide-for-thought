Object views

A note can hold a live view of your typed notes — the same list, table, gallery, map, board or timeline you get when you open a type from the Objects panel. It shows the notes as they are now, every time you open it, so a page about a trip can carry a map of every place you've noted for it without you keeping a list up to date.

Adding a view to a note

Start from the view itself: open a type from the Objects panel (or View Objects on a folder), then arrange it the way you want — pick a layout, sort it, choose columns, add filters. Then use one of the two buttons in its header:

Save as note
Makes a new note holding the view. You're asked for a name, and the note opens once it's made.
Copy as markdown
Copies the view so you can paste it into a note you already have, wherever you want it among your writing.

Both give you exactly the same thing: the view's layout, sorting, columns, folder and filters, all kept. You can paste the same view into as many notes as you like.

How it looks

In the editor, a view is a short block of text naming the type and how to show it. A Place map limited to one folder looks like this:

```object-view
{
  "typeId": "place",
  "layout": "map",
  "folder": "trip/prague"
}
```

You don't need to write or read this yourself — Save as note and Copy as markdown write it for you. In the preview it becomes the real view, and clicking a row, card or pin opens that note. The view's own filter controls and folder chip stay in its tab, so in a note you see just the notes it shows.

To change a view, make it again

The simplest way to change what a view in a note shows is to open the type's view, arrange it the new way, and copy or save it again in place of the old one.

A view sits in a box 360 pixels tall. To make it taller or shorter, drag the handle on its bottom edge, or click into the view and press Alt+↓ / Alt+↑; Alt+0 or a double-click on the handle puts it back. The new size is written into the note as a "height" line in the block, so ⌘Z undoes it like any other edit.

A board in a note

A Kanban board goes into a note the same way, and takes its arrangement with it: which field makes the columns, the order you dragged them into, and whether empty columns show. A Project board grouped by status, with done moved in front of active and empty columns hidden, looks like this:

```object-view
{
  "typeId": "project",
  "layout": "kanban",
  "groupBy": "status",
  "columnOrder": [
    "done",
    "active"
  ],
  "showEmptyColumns": false
}
```

"groupBy" names the field; without it, the board uses the type's first choice field. "columnOrder" puts the columns it lists first, in that order, and any it leaves out follow in their usual order; "" stands for No value. "showEmptyColumns" appears only when it's turned off. Each line is written only when it differs from the default, so a board you haven't rearranged is just its type and layout.

In the note, the board is for looking at. Its columns, counts and cards are the live ones, and clicking a card opens that note, but cards don't drag and have no Move to ▸, and the column headers have no menus. To move a card, open the type's board itself.

A timeline in a note

A timeline goes into a note with the stretch of time it was showing, as a "from" and a "to". A timeline of Events from 100 BC to the end of AD 14 looks like this:

```object-view
{
  "typeId": "event",
  "layout": "timeline",
  "from": "-0099",
  "to": "0014"
}
```

Both are dates written the way an event's are, at whatever precision suits: a year (1960), a month (1975-06), a day (1969-07-20), or a time (1969-07-20T14:05) for a view zoomed in to hours. Years before 1 CE take a minus sign, so -0099 is 100 BC. "from" starts at the beginning of what it names and "to" runs to the end of it, so "to": "0014" takes in all of AD 14. A "to" with a time is that moment. Leave out both and the timeline fits itself to its events, which is what a timeline you haven't zoomed saves. Leave out one and that side fits to the events. A "to" that comes before the "from" is ignored along with it, and the timeline fits all its events.

In the note, the timeline is for looking at. It shows the saved range without the −, + and Fit buttons, and scrolling or dragging doesn't move it. The keyboard still steps from event to event, ⏎ and a click still open them, and List still swaps in the list. To look at a different stretch of time, open the type's timeline, zoom it there, and save it again.

It stays current

Add a place, fill in a location, or change a field, and the view in your note shows it the next time you look. Renaming or moving a folder doesn't break a view that was limited to it — the view follows the folder to its new name.

In exports and on the web

When you export a note as a web page or PDF, or publish it as part of a website, its views appear as they do in the preview — a table is a table, a gallery is cards, a board is a read-only board, its columns wrapping onto the page and each card a link to its note, and a timeline is a still drawing of its saved range, each event a link to its note and approximate dates marked as such. The timeline's undated events are listed after it, and a very crowded one shows its first 30 lanes and a note of how many more there are. A map becomes a still picture framed just as the preview frames it, at the height you gave it, with the map's credit line beneath. If the map can't be drawn — say you're offline when you export — the places are listed as a table instead, so the page never shows an empty box.

A Markdown export keeps the view as the text you'd see in the editor.
