Sources

The Sources tab in Settings covers two things that only apply to identifier-based ingest and authenticated fetches — not the Sources panel itself. For what a source is, how collections and the reading queue work, and the ways you get a source into a project, see Left sidebar → Sources. This page is just the two settings: importing upstream subject tags, and privileged sites.

Ingest

A single toggle, on by default, that controls whether identifier ingest brings along the source API's own subject taxonomy:

Import upstream subject tags on source ingest
When on, ingesting by DOI, arXiv id, or PMID (File → Ingest Identifier…) applies the subject terms that API surfaces as namespaced tags on the new source — CrossRef's disciplinary subject taxonomy as crossref/…, arXiv's category codes as arxiv/…, and PubMed's MeSH descriptor headings as mesh/…. Turning it off doesn't touch tags already applied to existing sources; it only stops new ones from being added on future ingests. A source's right-click "Strip upstream tags" removes them after the fact, one source at a time.

Each namespace prefix identifies which API produced the tag, and the subject string is slugified (lowercased, non-alphanumerics collapsed to hyphens) to fit the tag panel's naming rules. Real examples produced by the ingest adapters:

crossref/sociology
From CrossRef's subject array on a DOI lookup — its broad disciplinary taxonomy (e.g. "Computer Science Applications" becomes computer-science-applications the same way; "Sociology" becomes sociology unchanged, which is the simplest case of the same slug rule).
arxiv/cs-lg
From an arXiv entry's category terms — the primary category first, then any additional ones on the entry. The API's dotted form (cs.LG) can't survive the tag slugger's rules, so the dot becomes a hyphen: cs.LG → cs-lg.
mesh/genetics
From PubMed's MeSH heading list on a PMID lookup — one tag per top-level descriptor name (qualifiers are ignored, since a single MeSH heading can carry several).
Only three upstream namespaces exist

CrossRef, arXiv, and PubMed/MeSH are the only identifier-ingest sources Minerva talks to, so crossref/…, arxiv/…, and mesh/… are the complete set of namespaces this toggle can produce — there's no per-namespace control, just the one switch for all upstream tagging. URL and file ingest never produce these tags; only DOI / arXiv id / PMID lookups carry a source-side subject taxonomy to import.

Privileged sites

A list of domains you've logged in to inside Minerva, so ingest fetches to those domains carry your session instead of hitting the page as an anonymous visitor. This is for institutional access and paid subscriptions — a paywalled article that renders fully once you're logged in.

Add site
Enter a domain (e.g. arxiv.org) and an optional label, then Add. Each site gets its own dedicated, persistent Electron session partition — cookies for one privileged site never mix with another's, or with Minerva's own browsing.
Login
Opens a plain browser window (no Minerva UI or APIs injected) pointed at the site's domain, using that site's partition. Log in as you normally would, then close the window — Minerva records the login time and keeps the session cookies in that partition for future fetches.
Logout
Clears the partition's cookies and storage, and resets the recorded login time to "never." The site stays in your list; you'd just need to log in again before it grants anything.
Remove
Deletes the site from the list and clears its partition's storage — same cookie wipe as Logout, plus the entry itself is gone.

What "privileged" actually grants: every ingest path — URL ingest, identifier ingest, and reference-stub resolution — routes its fetch through a privileged-site-aware wrapper. If the URL being fetched matches a configured site's domain (or a subdomain of it), the request goes through that site's authenticated session partition instead of a plain anonymous fetch; otherwise it falls back to a normal fetch. It has nothing to do with the browser clipper's trust model or with any kind of auto-ingestion — it only changes which cookies, if any, an ingest fetch carries.

Gotchas

  • Longest-domain-suffix wins when sites overlap. If you've added both a parent and a subdomain (unlikely, but possible), the fetch matches whichever configured domain is the more specific hostname suffix — not necessarily the one you added first.
  • Both settings are per-machine, not per-project. Like the rest of the Settings dialog's ingest-adjacent panels, the upstream-tags toggle and the privileged-sites list live under your home directory (Electron's userData), so they follow you across every project you open on this machine but don't travel with the project itself.
  • Turning the tag toggle off is not retroactive. It only changes what happens on the next identifier ingest — tags already on existing sources stay until you strip them manually, one source at a time, from that source's right-click menu.
  • A privileged site only helps if the fetch actually goes through Minerva. It authenticates ingest-time fetches (URL ingest, identifier ingest, stub resolution) — it doesn't log the browser clipper in, and it doesn't make a paywalled site auto-ingest anything on its own.
