Breadcrumbs

A thin bar sits above the note title showing where the current file lives in your folder tree — each folder in the path, then the note's own name. It's a persistent read-out, not a menu: there's nothing to open or trigger, just a live trail that tells you where you are and a fast way to jump back to that spot in the sidebar.

What the trail shows

The bar renders one segment per folder in the active file's project-relative path, followed by the note's own name as the final segment. A project note at research/interviews/q3-notes.md shows as research › interviews › q3-notes.

Folder segment
One per directory in the path. Clickable — jumps to that folder in the sidebar (see below). A note at the project root has no folder segments at all; the bar shows only the leaf.
Leaf segment
The current note's own name, always last. Rendered in italic to distinguish it from the folder chain, and set off with aria-current="page". Not clickable — you're already looking at it, so there's nothing for a click to do.
Heading chain (optional)
If Settings → Workspace → Behaviors has "show heading chain" turned on, a · separator and the chain of headings your cursor currently sits under trail after the leaf, each one clickable to jump the editor to that heading's line. Off by default — recomputes as you move the cursor, which some people find distracting in a bar that otherwise only changes on tab switches.

The project root itself isn't a segment — the trail starts at the first real folder under it. If a note lives directly in the project root, the breadcrumb bar shows only its leaf name with no folder segments before it.

Clicking a segment

Clicking any folder segment reveals that folder in the left sidebar: it switches the sidebar to the Notes panel, expands the clicked folder and every ancestor above it, and scrolls it into view. It doesn't select or highlight a row — just expands the tree and brings the folder on screen so you can see what else lives alongside the current note.

The leaf is inert

The note's own name at the end of the trail isn't a button. There's no "reveal current file" click target there — use the tab's right-click menu ("Reveal in Sidebar") if you want that instead, which additionally selects the file and expands only its ancestors, not the file itself as a folder.

Updating as you switch notes

The trail is derived directly from the active tab's file path, so it updates the instant you switch tabs or open a different note — no separate refresh step. There's no debounce on the folder chain itself; only the optional heading chain (when a cursor moves inside a heading) is throttled slightly so rapid cursor movement doesn't thrash the recomputation.

The bar disappears entirely when no note is open — there's nothing to show a path for on an empty pane.

Gotchas

  • No keyboard shortcut. Breadcrumbs are a persistent display element, not a triggered action — there's nothing to invoke from the command palette or bind a key to. Click a segment, or use the sidebar directly.
  • Long paths shrink the folders, not the leaf. When the trail is too wide for the pane, folder segments truncate with an ellipsis first — the leaf (your current note) is pinned to always stay fully visible, so a deeply nested path loses its middle folders before it ever crowds out the file you're looking at.
  • The root/project name never appears. The trail is relative to the project, not the filesystem — you won't see your project's own folder name as a leading segment.
