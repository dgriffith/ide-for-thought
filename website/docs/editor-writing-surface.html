The writing surface

The Source pane isn't a plain textarea with a monospace font bolted on. It's a single CodeMirror surface that understands markdown as you type — headers, emphasis, and links render styled in place, in the same pane you're editing, rather than staying inert characters until you switch to Preview. This page is about that pane's own character. For how Source relates to Preview and Side by side as separate view modes, see View modes.

What "live inline rendering" means

Minerva parses the buffer with @codemirror/lang-markdown and applies a token-driven highlight style directly on top of it (src/renderer/lib/components/Editor.svelte:470, src/renderer/lib/editor/minerva-highlight.ts). A heading line isn't just gray text with a # in front — the whole line is styled bold and in the accent color the moment CodeMirror recognizes it as a heading. Bold and italic spans pick up real font-weight and font-style the moment you close the ** or _. Wiki-links and URLs get a soft rounded chip and become clickable (src/renderer/lib/editor/link-decorations.ts:165-173).

The important distinction from Obsidian-style "live preview" editors: Minerva never hides the markdown delimiters. The #, **, ==, and [[/]] stay on screen, styled through, rather than disappearing until your cursor lands nearby. A comment in the highlight-span source states the convention directly: "We don't hide the == delimiters — keeping them visible is the convention for inline markup... the user can see exactly what they wrote" (src/renderer/lib/editor/highlight-decorations.ts:6-9). There's no cursor-triggered reveal because nothing is ever concealed — what you see is always the literal file content, styled, not a rendered substitute.

Headers
Styled bold, in the accent color, as soon as the line parses as a heading. The # markers stay visible as part of the line (t.heading, minerva-highlight.ts:102).
Bold / italic / strikethrough
**bold**, _italic_, and ~~struck~~ render with real weight, slant, or a line-through the moment the span closes — the asterisks, underscores, and tildes stay visible, just styled along with the text (minerva-highlight.ts:103-105).
Highlights — ==text==
A tinted background matching the same color the Preview pane uses, painted live while typing. Delimiters are intentionally not hidden (src/renderer/lib/editor/highlight-decorations.ts).
Wiki-links & URLs
A soft accent-tinted chip, no underline, cursor turns into a pointer on hover — a mark decoration, not a widget, so the caret can still move through the link text to edit it (src/renderer/lib/editor/link-decorations.ts:178-194). Hovering one briefly also pops a preview tooltip of the target note (src/renderer/lib/editor/link-preview.ts).
Footnote refs & definitions
[^label] renders underlined and clickable, jumping between a reference and its definition on click; hovering a reference pops a tooltip of the definition body (src/renderer/lib/editor/footnote-decorations.ts, footnote-preview.ts).
Runnable code fences
A ▶ run marker appears in the gutter next to any executable fence (SPARQL, SQL, Python); results write back into the note as a companion ```output block right below the fence, not into a separate panel (src/renderer/lib/editor/compute-cells.ts).

Not a textarea, and not a second copy of the file

Two things follow from the pane being CodeMirror rather than a bare <textarea>: it understands markdown structure well enough to fold the frontmatter block, match brackets, and drive autocomplete — see Link autocomplete — and it renders through theme tokens, so switching themes re-skins the editor's syntax colors along with everything else, live, with no rebuild.

The pane is the file, not a preview of it

What you're looking at in Source is the exact text of the .md file on disk, styled — not a separate rendering pass like Preview's. There's no intermediate "draft" state: every keystroke is the buffer, and every save re-indexes it into the knowledge graph immediately, the same as any other edit. See Notes for how saves feed .minerva/graph.ttl.

Gotchas

  • Plain-text files skip all of this. A file Minerva treats as plain text (not markdown) gets the bare editing buffer with no markdown language, no link/footnote/highlight decorations, and no compute-cell gutter — Editor.svelte:467-535 gates the entire markdown rendering stack behind a markdown check.
  • Delimiters are never hidden. If you're coming from an editor that conceals **/#/[[…]] until the cursor is nearby, expect Minerva's Source pane to look "busier" — that's deliberate, so what you see always matches what's actually in the file.
  • Links are marks, not widgets. The chip styling on a wiki-link doesn't replace the text with something else — you can still click into the middle of [[Some Note]] and edit the target directly, because the brackets and text are still real, editable characters underneath the styling.
