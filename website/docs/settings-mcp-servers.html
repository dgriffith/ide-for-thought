MCP Servers

The Model Context Protocol (MCP) is a standard way for a tool server to offer tools to an AI. This tab is Minerva on the consuming side: point it at somebody else's MCP server and the tools that server offers become available to the assistant while you're chatting. That's the opposite direction from MCP use, which hands your thoughtbase to an outside agent — see Two directions below.

Adding a server

Click Add server…, give it a Name, and choose one of two kinds:

Local command (stdio)
Minerva launches the server itself as a background program. Fill in the Command (for example npx), any Arguments one per line, and any Environment variables as KEY=VALUE, one per line — that's where an API key the server needs goes.
Remote URL (http)
Minerva connects over the network to a server somebody else runs. Fill in the URL. If it requires a login, Minerva handles that — see Needs authorization below.

The name is how the assistant refers to the server, so keep it short and distinct — two servers sharing a name can't be told apart. A server you've just added starts switched off: nothing is launched or contacted until you turn it on.

What the status says

○ Disconnected
Configured, but nothing is running. Where every server sits until you switch it on.
… Connecting
An attempt is in flight — starting the command, or reaching the URL.
● Connected
Working. A tool count appears underneath; open it to see every tool the server offers, with its description.
⚠ Needs authorization
A remote server wants you to log in, and Minerva won't open a browser at you unasked. Click Connect on that row to finish signing in; afterwards the sign-in is remembered and later connections are silent.
✕ Error
The attempt failed — a command that isn't installed, a URL that doesn't answer. The reason is printed under the row, and the server stays configured so you can Edit it and try again.

Switching on, connecting, editing

The switch at the start of each row is the whole control: on connects straight away, off disconnects. Servers left on are reconnected in the background each time you start Minerva, so a working setup stays working. Connect appears on a row that's on but not connected — use it to retry after a failure or to complete a sign-in. Edit changes the name or the address; changing the address drops the existing connection, since it no longer says where the server is. Remove disconnects and forgets the server.

Screenshot — the MCP Servers settings panel: the Add server… button, and a configured server's row showing its switch, kind, status and expandable tool list.

Using the tools in a conversation

Once a server is connected its tools reach the assistant automatically — nothing to enable per tool, nothing to type. Ask for something the server can do and the assistant reaches for it, naming the server and tool in the transcript. Only connected servers count: one that's off, failing, or offering no tools simply isn't mentioned to the assistant, so a broken server costs you nothing but the row.

These calls aren't gated

Minerva's approval gate protects your notes and your graph — nothing the AI proposes there lands until you approve it. A tool on a third-party server isn't your graph: it's someone else's service, and calling it happens directly, with no confirmation step. The tool list shows whether a tool claims to be read-only, but that claim comes from the server and is a hint, not a guarantee. Add servers you'd trust to act on your behalf.

Two directions, one protocol

This tab
Minerva is the client. Other people's tools come in, and Minerva's own assistant uses them while you chat.
MCP use
Minerva is the server. Your thoughtbase goes out to an outside agent — Claude Desktop, a coding agent — which can search it and file gated proposals back.

They share only the protocol, and can run at once. Nothing here changes what an outside agent sees, and starting Minerva's own MCP server adds nothing to this list — which is kept per computer, not per thoughtbase, so it's the same whichever thoughtbase is open.
