Tables

The Tables panel lists every queryable table in your project — both standalone .csv files and captioned markdown tables written inside notes — each registered into the same in-memory DuckDB, ready to query with SQL. A row's source is labelled (csv or note) so you always know whether its rows live in a file or a note.

Two kinds of table, one SQL engine

A standalone .csv file registers automatically. A markdown pipe table inside a note registers only when you give it a name — a Pandoc-style caption line Table: <name> directly above it (see Tables & CSV). Both end up as tables in the same DuckDB connection with the same naming rules, so SELECT * FROM <name> works identically whichever kind you have. An uncaptioned markdown table is unchanged — it stays graph-only (extracted to .minerva/graph.ttl as CSVW triples on save) and never appears in this panel.

How a table gets here

On project open, Minerva walks the project folder and registers every .csv file it finds as an in-memory DuckDB view — the view is lazy, so DuckDB re-reads the file from disk on every query rather than caching stale content. The file watcher keeps this live afterward: adding, editing, or deleting a .csv anywhere in the project registers, re-registers, or drops its view automatically, and the panel refreshes to match. There's no import step and no dialog — drop a CSV in the folder and it's queryable.

The SQL identifier for a CSV is derived from its path by default (slashes and punctuation become underscores — notes/data/2024-experiment.csv becomes notes_data_2024_experiment), but you can pin an explicit name. A companion markdown note in the same folder with a matching filename stem (experiment.csv ↔ experiment.md) can set table_name: in its frontmatter to override the derived name — useful for giving a table a shorter or more memorable identifier than its path would produce.

Captioned markdown tables

A pipe table written inside a note becomes queryable the moment you caption it. Put a Pandoc-style line directly above the table:

Table: Q3 Sales
| item  | amount |
| ----- | ------ |
| pens  | 3      |
| ink   | 7      |

The caption (Q3 Sales) is sanitized to a SQL identifier by the same rules CSV filenames use (spaces and punctuation become underscores, a leading digit gets a t_ prefix), giving the table name Q3_Sales. The table is materialized into the same DuckDB, and its rows are typed by the same CSV sniffer the file path uses — so SELECT sum(amount) FROM Q3_Sales sums numerically. Saving the note re-registers it; removing the caption or deleting the note drops it. This is opt-in: a table with no Table: line is left exactly as before, graph-only and absent from this panel.

Two tables, one name

All CSV files and captioned markdown tables share a single name namespace, so a collision is detected across both kinds. If two would derive the same name, the second is skipped rather than silently replacing the first — you'll see a toast pointing at the conflict. CSV files win: when a CSV and a note table collide, the note table is the one skipped. Rename the Table: caption (or set a table_name: override on a CSV's companion note) to disambiguate; the skipped table's rows simply aren't queryable until you do.

What each row shows

The panel is a flat, alphabetically-sorted list (by file path) with a filter field above it that matches against both the table name and the file's relative path as you type.

Table name
The SQL identifier — the derived or overridden name described above — shown in monospace as the row's primary label.
Source tag
A small csv or note tag beside the name says where the table's rows live — a standalone file or a note's caption. Note tables also show their source note on the meta line.
Row / column counts
A live count queried straight from DuckDB — 3 rows · 5 cols, for example — not a cached figure from when the table was first registered.
Source path (on hover)
The project-relative path of the CSV file — or, for a note table, the caption plus the source note — isn't printed in full in the row itself, but it's the row's tooltip.

Clicking a table

Clicking a row doesn't open the underlying file or note — it opens a new SQL query tab pre-filled with SELECT * FROM <table name> against that table, so you land straight on its data. From there it's an ordinary compute-cell-style query surface: edit the SQL, re-run it, and it executes against the same in-memory DuckDB instance the panel itself is backed by.

Right-clicking a row opens a context menu with four actions (the third is source-aware):

Query (SELECT *)
Same action as a left click — opens the query tab.
Copy Table Name
Copies the SQL identifier to the clipboard, for referencing the table in a query you're already writing elsewhere (a compute cell, for instance).
Open CSV / Open Note
For a csv row this opens the raw .csv file as a file tab, the same as selecting it in the notes tree. For a note row it opens the source note that defines the table instead. Either way there's no separate export or view-as-table step.
Reveal in Finder
Shows the source file — the CSV, or the note — in the OS file browser.

Gotchas

  • Empty project shows a hint, not a blank pane. With nothing registered, the panel reads "No tables yet. Drop a CSV into the thoughtbase, or add a Table: caption above a markdown table." instead of an empty list.
  • Only captioned markdown tables appear. A pipe table with no Table: line above it is graph-only and won't show here or be SELECT-able — that's deliberate, so ordinary prose tables don't clutter the SQL namespace. If a note table you expect is missing, check the caption is on the line directly above the header row (one blank line between is fine).
  • CSV reads are live; note-table reads are re-materialized on save. Editing an already-registered CSV is reflected immediately — its DuckDB view re-reads on every query. A markdown table has no backing file, so its rows are materialized into DuckDB when the note is saved and re-materialized on each subsequent save. Adding a brand-new file, or a rename, relies on the file watcher (normally instant); if something doesn't show up, Query → Rebuild All Indexes forces a full re-scan of every CSV and captioned table.
  • This is a separate DuckDB instance from any per-note compute cells. The panel and its query tabs share one in-memory database per project — every registered table, CSV or note, is queryable from any query you open, including a note's own ```sql cells. Column names and types are mirrored into .minerva/graph.ttl; a captioned note table's rows also remain in the graph as CSVW triples, joined back to the SQL table via minerva:fromNote.
