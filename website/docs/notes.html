Notes

A note is a plain .md file — nothing more. It can live anywhere in your project's folder tree, no dedicated "notes" directory required, and it can optionally start with a block of YAML frontmatter carrying structured metadata. Everything else — links, formatting, embedded content — is markdown written in a text editor, which is what makes a Minerva project just a folder of files you can open, edit, and back up with anything else that understands plain text.

The note lifecycle

Notes are managed from the sidebar tree, the command palette, or the File menu:

Create
File → New Note (⌘N), or "New Note" from the command palette. A dialog asks for a name and, optionally, a starting template — there's no silent "Untitled" default and no auto-numbering to dodge a collision, so pick a name that doesn't already exist.
Rename
From the note's context menu in the sidebar. Prompts for a new name with the current one pre-filled. Renaming also rewrites every wiki-link elsewhere in the project that pointed at the old name, so incoming links don't go stale.
Move
Drag the note to a different folder in the sidebar tree.
Delete
From the note's context menu in the sidebar. Minerva checks first whether anything outside the project still links to the file; if it's clear, you get a plain confirmation — "Delete note "name"?" — with a "don't ask again" option. No red styling: deleting a note is a normal operation, especially with git backing every project.

Every save updates the graph

There's no separate "index" or "sync" step. The moment you save a note, Minerva parses it and immediately re-indexes it into .minerva/graph.ttl — extracting the title, tags, wiki-links, frontmatter metadata, any embedded Turtle blocks, and table data. The knowledge graph is always a live reflection of what's on disk, not a snapshot you have to remember to refresh.

What you can put in a note

Beyond prose, a note can embed any of the following. Each has its own page with the exact syntax, how it renders, and any gotchas to know about:

🔗

Links

Wiki-links, typed relationships, and how they build the backlink graph.

 💡

Callouts & cards

Titled note, tip, and warning-style boxes, plus front/back flashcard callouts.

 ∫

Math

Inline and display equations, rendered with KaTeX.

 🔀

Diagrams

Flowcharts, sequence diagrams, and anything else Mermaid draws.

 📊

Charts

Interactive Vega and Vega-Lite charts, live in the note.

 🧮

Code & compute cells

Syntax-highlighted code, plus runnable SPARQL, SQL, and Python cells.

 📋

Tables & CSV

Markdown tables that double as structured data via CSVW.

 🖼️

Images

Drag, paste, or link images — stored right alongside your notes.

 🎬

Media

YouTube videos as click-to-open poster cards, no embedded player.

 🦶

Footnotes

Asides and citations that collect at the bottom of the note.

 🖍️

Highlights

Mark a passage as important with a tinted inline span.

 ☑️

Task lists

Checkboxes that toggle in preview and write straight back to source.

 🐢

Turtle / RDF

Hand-author graph triples directly inside a note.

 🏷️

Frontmatter

YAML metadata that drives the app and feeds the graph.
