Maintenance

Notes, search, tables, and semantic search all stay in sync automatically as you work — indexing happens on save, not on a schedule you manage. These six actions are the manual escape hatch for when that assumption breaks down, not a routine you're expected to run.

The actions

Rebuild All Indexes
File menu
A full rescan — the knowledge graph, full-text search, and every registered CSV table are all rebuilt from what's on disk, rather than the incremental update a normal save triggers. Reach for this if something looks stale or inconsistent and you want to rule out a missed update.
Rebuild Semantic Index
File menu
Forces a full re-embed of the corpus. Normal backfill (a new note, or the embedding model changing) already happens automatically in the background — this is the explicit "start from scratch" option for suspected corruption. Runs non-blocking, with progress shown in the status bar.
Interrupt Cell
File menu
Stops a running Python cell without restarting the kernel — everything else the kernel holds (variables, imports) stays intact. Unix only. No default keyboard shortcut is assigned (the Jupyter-standard Cmd+. collides with macOS's own Zoom In).
Restart Python Kernel
File menu
Wipes every notebook's namespace — all variables, imports, and Python's own module cache. Needed after editing a .py helper file elsewhere in the project, since the kernel caches imports and won't pick up your edit otherwise (see Editor for the compute-cell side of this).
Clear Recent Thoughtbases
File menu
Wipes the open-recent list shown when you launch Minerva. Bookkeeping only — no project data is touched.
Export Knowledge Graph…
Export menu
Dumps the live RDF store to a .ttl file you choose — the one item here that isn't strictly "fix something," more a raw escape hatch to the underlying data. See Export for everything else that menu covers.

What's deliberately not here

There's no "verify thoughtbase integrity" or "repair broken links" action, and no cache-clearing beyond the two rebuild actions above. The graph, search index, and tables are designed to stay correct via normal on-save indexing — this menu exists for the rare case where that assumption doesn't hold, not as a checkup you should run out of habit.
