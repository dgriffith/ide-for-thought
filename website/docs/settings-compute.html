Compute

The Compute tab is one thing: which Python interpreter Minerva runs your python cells with. There's no separate trust switch to configure here — the one-time consent prompt for running Python at all lives at the point you actually run a cell, not in Settings. See Code & compute cells for the fence syntax, how output is written back into a note, and the full execution-trust model.

Python interpreter

This tab has a single field: a path to a Python executable. It's a per-machine override, not a per-project one — every thoughtbase you open on this computer shares whatever interpreter you set here.

Python interpreter path
A text field for the path to the Python binary Minerva should invoke — for example /Users/you/.minerva-venv/bin/python. Left empty, Minerva resolves an interpreter in order: the MINERVA_PYTHON environment variable, then python3 on $PATH.
Browse…
Opens a native file picker to select the interpreter binary instead of typing a path. Selecting a file probes it immediately, so you see right away whether it's runnable.
Probe
Runs python --version against whichever path is currently in the field (or, if the field is empty, against whatever the resolver would currently pick) and reports the result inline — the resolved version string on success, or the interpreter's own error text on failure. Probing doesn't save anything; it's a dry run.
Save
Writes the current path as the per-machine override. Disabled when the field matches what's already saved, so it only lights up once there's an actual change to persist.
Save & Restart Kernel
Saves the path and restarts the persistent Python process immediately, so the very next cell you run picks up the new interpreter. Restarting wipes the kernel's namespace — variables and imports from earlier cells in any open note are gone, the same as if you'd started a fresh Minerva session.
Clear override
Empties the saved path, returning to the MINERVA_PYTHON / python3 resolution order above. Only appears once a path has been saved.

Where the trust prompt actually is

The tab's sub-line in the Settings menu reads "Python interpreter · trust," but there's no toggle for it here — the trust model isn't a setting you configure in advance, it's a one-time confirmation dialog that appears the first time you run a Python cell in a given project. Declining leaves the cell unrun until you approve it later; approving is remembered for the rest of that project. That prompt, what it gates, and why SPARQL and SQL fences skip it entirely, are covered in Code & compute cells — Approval and the knowledge graph. This page is only about which interpreter binary gets used once that trust is in place.

Gotchas

  • A saved path that stops existing fails at run time, not save time. Saving doesn't validate the path — Probe does, but Save doesn't require a successful probe first. If an interpreter gets uninstalled, moved, or was on a drive that's no longer mounted, the saved override stays in place and the next cell run simply fails with the interpreter's own error text in the output block. Come back to this tab, Probe to confirm, and Browse to a valid binary.
  • It's per-machine, so it doesn't travel with the project. Open the same thoughtbase on another computer and it resolves the interpreter fresh on that machine — the environment variable or python3 on that machine's PATH, unless you set an override there too. A project's notes never encode which interpreter produced their output.
  • Restarting the kernel is a real reset. Any variable, DataFrame, or import built up across a note's Python cells is gone after Save & Restart Kernel. If you need that state, re-run the note's cells from the top afterward rather than assuming Minerva carries anything forward.
  • Probing the empty field probes the resolver, not "nothing." With the path field blank, Probe still runs against whatever MINERVA_PYTHON or python3 would resolve to — so a failed probe on an empty field usually means neither of those is set up, not that probing was skipped.
