Markdown formatting

Minerva renders standard markdown, plus a set of extensions for research and knowledge work. This page is a scannable reference — syntax on the left, what it renders as on the right — not a tutorial. The basics are covered in full below; anything more elaborate links out to its own page with the complete syntax and behavior.

The basics

Headers, emphasis, lists, blockquotes, and inline code follow standard CommonMark, with one deliberate deviation noted below.

# … ######
Headings, level 1 through 6 — # H1, ## H2, and so on. Minerva is ATX-only: the underline style (Heading\n---) is deliberately disabled, so a line followed by a row of dashes stays plain text rather than becoming a heading. Every rendered heading gets a stable id for wiki-link anchors like [[note#heading]].
**bold** / __bold__
Both delimiters work — bold text.
*italic* / _italic_
Both delimiters work — italic text.
- item / * item / 1. item
Unordered lists (either - or *) and ordered lists (any number followed by .). Indent a nested item by four spaces to sublist it. A list item starting with [ ] or [x] becomes an interactive checkbox instead — see Task lists.
> quoted text
A blockquote, indented and set off with a rule along the left edge. Prefix the first line with [!type] — [!note], [!tip], [!warning], [!card], and more — and it becomes a titled, colored callout instead of a plain quote. See Callouts & cards.
---
A horizontal rule, as long as it sits on its own line with a blank line before and after. The one exception: three dashes as the very first line of the file instead opens a YAML frontmatter block, closed by a matching --- further down.
`inline code`
Monospaced inline code, no syntax highlighting.
```lang … ```
A fenced code block, syntax-highlighted by language. Fence a block sparql, sql, or python and it becomes a runnable cell with its result written back into the note. See Code & compute cells.

Everything else

These have their own page with full syntax, rendering details, and any gotchas — this row is just a pointer:

Links & wiki-links
[[Note Title]] resolves and renders as a live link into the knowledge graph; standard [text](url) links also work. Links can carry a relationship type, like supports or rebuts.
Images
Standard ![alt](path) syntax. PNG, JPEG, GIF, WebP, SVG, and AVIF render inline and can be clicked to enlarge.
Tables
Standard pipe-delimited markdown tables — header row, alignment row, data rows. Every table is also parsed into the graph as CSVW structured data on save.
Footnotes
An inline [^id] marker paired with a [^id]: definition anywhere in the file, collected at the bottom of the note.
Highlights
Wrap text in ==double equals== for a tinted inline highlight span.
Task lists
A list item starting with [ ] or [x] renders as a clickable checkbox that writes its state straight back to the source.
Math
$inline$ and $$display$$ LaTeX, rendered with KaTeX — the same convention as Pandoc.
Diagrams
A ```mermaid fence renders as a live diagram — flowcharts, sequence diagrams, and anything else Mermaid draws.
Charts
A Vega or Vega-Lite JSON spec in a fenced code block renders as an interactive chart, optionally bound to a live SPARQL query or dataset.
Callouts & cards
A blockquote whose first line is [!type] becomes a titled note/tip/warning-style box; [!card] renders as a front/back flashcard.
Turtle / RDF
A ```turtle fence lets you hand-author graph triples directly in a note; Minerva merges them into .minerva/graph.ttl on save.
