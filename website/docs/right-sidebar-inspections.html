Inspections

Inspections is a battery of epistemic health checks that run against your whole project's knowledge graph — not just the open note — and surface structural or evidentiary problems in your claims, grounds, and warrants: unsupported claims, missing warrants, contradictions between established claims, broken links, and a handful of source-hygiene checks. Every result is a read-only flag. Nothing here writes to the graph, and nothing goes through the Proposal/approval system — it's diagnostics, not authorship.

Not currently in the UI

This panel's tab was deliberately removed from the right sidebar before the v1.0 release — the feature wasn't ready for general use. The engine behind it keeps running: health-checks.ts still executes its checks on a schedule, and the panel component itself is untouched. There's no setting to bring the tab back; that only happens in a future release. This page documents the panel as it exists in the code, for whenever the tab returns.

What it actually checks

The checks are a fixed, hardcoded list in src/main/graph/health-checks.ts — not a general query builder and not user-configurable. Each one is a SPARQL query against .minerva/graph.ttl, run in parallel by runAllChecks():

Unsupported claim
A thought:Claim with no other node thought:supports-ing it — a claim asserted with no grounds behind it at all.
Missing warrant
A claim that has thought:Grounds supporting it but no thought:Warrant connecting the grounds to the claim — evidence exists, but the reasoning link explaining why it counts is absent.
Missing backing
A warrant with no thought:Backing behind it — the reasoning link exists, but nothing justifies trusting the warrant itself.
Contradiction
Two claims both marked thought:hasStatus thought:established that rebut each other — two things the graph currently treats as settled, disagreeing.
Source hygiene
A cluster of checks unrelated to the claim/grounds/warrant structure: stale notes, malformed DOIs, sources missing metadata, aged-out stubs, sources that are cited but never actually read, duplicate sources sharing a DOI or URL, and broken wiki-links, anchors, or citation keys.

How it runs

Checks run automatically once when a project opens, and again every five minutes after that. The panel's own Run button forces an immediate pass rather than waiting for the next scheduled sweep. There's no write path anywhere in this code — it only reads the graph, so running an inspection can't trigger the LLM write-guard or the approval engine, because nothing is written.

Gotchas

  • Clicking a result doesn't navigate. Unlike Backlinks, Outline, or every other panel that jumps you to a location, clicking an inspection result opens a new conversation pre-seeded with that inspection's message — the intended next step is to discuss and resolve it with the AI, not just to look at where it is.
  • Plain prose produces nothing. A note with no thought:Claim/Grounds/Warrant structure at all won't fail any check — it simply won't generate any rows, since none of the checks have anything to fire against.
