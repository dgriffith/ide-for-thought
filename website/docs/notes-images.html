Images

Embed images in your notes using standard markdown syntax. Minerva supports common image formats — PNG, JPEG, GIF, WebP, SVG, and AVIF — and stores them in your project alongside your notes. Upload images by dragging and dropping, pasting from your clipboard, or typing the path directly. In preview, images are displayed inline and can be clicked to enlarge; in the editor, broken or missing images are flagged so you can spot them immediately.

Syntax

Images use the standard markdown syntax: ![alt text](path/to/image). The alt text describes the image for accessibility and appears as a tooltip when you hover over it in the preview. The path can be relative to your note's directory, project-relative, or an absolute URL.

![alt](path/image.png)
Basic image. Displays the image inline at its natural size. The alt text is required for accessibility; write a brief, accurate description of what the image shows.
![](path/image.png)
Empty alt text. Allowed when the image is purely decorative, but discouraged — even decorative images benefit from a description. Use sparingly.
![alt](../../assets/image.png)
Relative path with parent traversal. A path starting with ../ goes up one level for each ../, making it easy to reference images stored outside the note's directory. Minerva normalizes all .. segments so there's no way to escape the project root.
![alt](image.png)
Sibling reference. A bare filename looks for the image in the same directory as the note. Useful for images stored right alongside the note file.
![alt](https://example.com/image.png)
Absolute URL. External images pass through unchanged. They're fetched when the note is viewed and displayed inline just like local images.

Uploading images

You can upload images in three ways: drag and drop, paste from clipboard, or manual entry. All uploads are stored in your project's .minerva/assets/inline/ directory, a hidden folder that Minerva manages for you.

Drag and drop

Drag an image file from Finder (or your file explorer) into the editor. The image is uploaded and a markdown link is inserted at the cursor. The path is computed relative to the note's directory so it resolves correctly regardless of where the note lives in your project.

Paste from clipboard

Copy an image (e.g., a screenshot or a photo from your browser) and paste it into the editor with ⌘V (or Ctrl+V). The image is uploaded and inserted immediately. If your system clipboard contains multiple items (image and text, for example), only the image is used.

Manual paths

Type or paste an image path directly into the markdown. This works for images you've already moved into your project. A relative path like ![alt](../photos/sunset.jpg) resolves relative to the note's directory.

How images are stored

When you upload an image via drag and drop or paste, Minerva:

  1. Validates the image format (must be PNG, JPEG, GIF, WebP, SVG, or AVIF).
  2. Computes a SHA-256 hash of the file content and uses the first 12 hex characters as a prefix.
  3. Sanitizes the original filename (if available) to remove unsafe characters.
  4. Writes the file to .minerva/assets/inline/ with a name like a1b2c3d4e5f6-screenshot.png.
  5. Inserts a markdown link at the cursor with a path relative to the note's directory.

The hash prefix gives you automatic deduplication: if you paste the same screenshot twice, or drag the same file in two different notes, Minerva detects the match by hash and stores it only once. This keeps your project lean.

File size limit

Images can be up to 5 MB. Larger files are rejected with a message. If you need to embed a large image, compress it first using your image editor or a tool like ImageOptim (Mac) or FileOptimizer (Windows).

How images render

In preview, images are displayed inline at their natural size. Clicking an image opens a lightbox view — a full-screen overlay of the image with a close button (or press Esc). This lets you see details and inspect the full resolution without leaving your note.

In the source editor, image references appear as syntax-highlighted links.

Local images (those with relative paths or stored in your project) are fetched and converted to data URLs for display. This means the preview doesn't need network access to show your images — they're always available.

Supported formats

Minerva accepts the following image formats:

PNG
Lossless compression, supports transparency. Best for diagrams, screenshots, and graphics.
JPEG
Lossy compression, smaller file sizes. Best for photographs and complex images.
GIF
Lossless, supports animation. Animated GIFs play in preview.
WebP
Modern format with better compression than PNG and JPEG. Increasingly supported across tools.
SVG
Scalable vector graphics. Perfect for diagrams, icons, and line art. Embedded SVGs scale to any size without pixelation.
AVIF
Newest format with excellent compression and quality. Best for new projects if compatibility isn't a concern.

Other formats (TIFF, BMP, HEIC, etc.) are rejected when you try to upload them. External images linked via URL can be in any format your browser supports, but uploads are restricted to these six to keep your project portable and future-proof.

Understanding relative paths

All image paths in markdown are resolved relative to the note's directory, not the project root. This matters when your notes and images are organized in folders.

Example directory structure:

my-project/
  articles/
    research.md
    figures/
      diagram.png
  archive/
    old-note.md
  assets/
    logo.png

In articles/research.md, you'd link the diagram as:

![Diagram](./figures/diagram.png)

The ./ means "current directory" (the articles/ folder). To reference the logo from `articles/research.md`, you'd go up one level and into assets/:

![Logo](../assets/logo.png)

And from `archive/old-note.md`, the same logo is reached by going up one level (to the project root) and into assets/:

![Logo](../assets/logo.png)

Minerva normalizes paths automatically, so even if you write ../articles/../assets/logo.png, it resolves to ../assets/logo.png and works correctly. Paths are also protected — there's no way to use .. to escape outside your project root.

Gotchas

  • Missing or broken paths. If a relative path points to a file that doesn't exist or can't be read, the image renders with a broken-image indicator in preview (usually a missing-image icon), and the source editor highlights it visually. Check the path and make sure the file exists in the right location.
  • Case sensitivity. On macOS and Windows, filenames are case-insensitive by default, but uploaded images use lowercase stems for deduplication. If you reference an image as MyPhoto.jpg and it's stored as myphoto.jpg, you might see inconsistent behavior on Linux (which is case-sensitive). Use consistent lowercase filenames or use the exact case returned by drag-and-drop uploads.
  • Special characters in filenames. When you drag a file with spaces or special characters (e.g., My Screenshot (2).png), Minerva sanitizes the stored filename to my-screenshot-2.png for filesystem safety. The markdown reference is still inserted correctly, but don't manually rename or move files in the .minerva/assets/inline/ directory — Minerva expects the hashed names to be stable.
  • External images and offline viewing. Images linked by absolute URL (e.g., https://example.com/image.png) are fetched when you view the note. Without a network connection, the preview shows a broken-image icon. Local images work offline because they're stored in your project.
  • SVG injection and security. SVG files embedded in notes run as part of the document, so they can include JavaScript or other embedded content. Minerva runs SVGs in a sandboxed context with strict CSP rules, so malicious scripts can't escape the preview. Still, be cautious with SVGs from untrusted sources — treat them like any executable code.
  • Very large images. While Minerva stores images up to 5 MB, displaying very large images (e.g., 10000×10000 pixels) can slow down the preview or use a lot of memory. If you need high-resolution images, consider breaking them into tiles or using a lower-resolution version for the note.
  • Renamed or moved notes. When you rename a note or move it to a different directory, the relative image paths break if you move the note without updating the image references. Use the file explorer or the refactoring tools to move notes — Minerva updates paths automatically when it can. If you move a note manually, the image links will have broken paths until you fix them.
