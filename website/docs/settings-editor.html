Docs/Settings/Editor

Editor

The Editor tab in Settings holds the handful of preferences that change how the markdown editor and its preview behave while you type — tab size, wrapping, line numbers, whitespace visibility, frontmatter collapsing, and numbered section headings. These are per-machine editing preferences, distinct from the Editor doc section, which covers the editing surface itself rather than its settings.

Settings

Six fields, all with sensible defaults — most people never need to open this tab:

Tab size
Number input, range 1–8. Default 2. Controls how many spaces a tab or auto-indent inserts.
Word wrap
Checkbox. Default on. Long lines wrap to fit the editor width instead of scrolling horizontally.
Show line numbers
Checkbox. Default on. Toggles the gutter running down the left edge of the editor.
Show whitespace
Checkbox. Default off. Renders spaces and tabs as visible marks — useful for chasing down stray trailing whitespace or mixed indentation.
Always collapse frontmatter
Checkbox. Default off. Automatically folds the YAML frontmatter block at the top of a note when it's opened, instead of leaving it expanded.
Numbered section headings
Checkbox. Default off. Prefixes each H2 in the preview with a "§ 01" section numeral — H1 and H3+ are untouched, and the raw markdown source is untouched too, since the numeral is a rendered decoration, not text written into the file. Best for long-form essays; leave off for journals and lists.

Screenshot — Settings → Editor tab
The Editor tab of the Settings dialog: the Tab size number field followed by checkbox rows for Word wrap, Show line numbers, Show whitespace, Always collapse frontmatter, and Numbered section headings, the last two with their explanatory hint text visible beneath the label.
Preview-only, not source

Numbered section headings is purely a rendering choice: it changes what the preview pane shows, via a CSS counter on the H2 elements, and never rewrites the note's markdown. Turning it off again removes the numerals from the preview immediately — there's nothing in the file to clean up either way.
