Docs/Settings/Notes

Notes

The Notes tab in Settings controls where the note-creating commands file what they create — Extract Selection, Split Here, and Split by Heading (the Refactoring subsection), and New note from excerpt (the Excerpt notes subsection) — plus the templates that shape what gets written into the new note and left behind in the source.

Refactoring

These settings apply to the three note-splitting commands. They're per-machine preferences, not part of a project — Minerva keeps them in your browser profile's local storage, so they follow you across every thoughtbase you open on this machine but don't travel with a project to another computer.

Destination for new notes
Dropdown with three options: Same folder as source note (default), Thoughtbase root, or Custom folder (template). Applies to Extract Selection, Split Here, and Split by Heading alike.
Custom folder template
Only shown when destination is Custom folder (template). A text field for a project-relative path built from tokens, e.g. notes/{{date:YYYY}}/{{date:MM}}. Left blank, it resolves to the thoughtbase root.
Filename prefix
Text field, empty by default. Prepended to every refactored note's generated filename, using the same token syntax as the folder template — e.g. {{date:YYYYMMDDHHmm}}- for a Zettelkasten-style timestamp prefix.
Normalize heading levels in extracted notes
Checkbox, off by default. When the extracted body's shallowest heading is H2 or deeper, shifts every heading up so it becomes H1. Only touches the new note's body — the source note is never rewritten.
Transclude by default
Checkbox, off by default. When on, refactor commands leave behind ![[new-note]] in the source instead of [[new-note]], so the preview inlines the extracted content rather than just linking to it. Disabled (greyed out) whenever a link template is set below, since the template takes over that decision.
Link template
Multi-line text field, empty by default. What to put in the source note in place of the extracted content. Blank means Minerva falls back to a plain wiki-link, or a transclusion if the toggle above is on. Precedence is: link template, if set, always wins over the transclude toggle.
Refactored note template
Multi-line text field, empty by default. Wraps the body of every note these commands create. Blank means the extracted content is used as-is, unwrapped.

Template tokens

The destination template, filename prefix, link template, and refactored-note template all share one token syntax. A token is anything inside double braces:

{{date}}               ISO date (YYYY-MM-DD) in local time
{{date:FORMAT}}        Custom date format — FORMAT is built from YYYY, MM, DD, HH, mm, ss
{{title}}              The source note's title
{{source}}             The source note's project-relative path
{{new_note_title}}     The new (extracted) note's title
{{new_note_content}}   The new note's raw body — only available in the refactored-note template

Not every template accepts every token — {{new_note_content}} only makes sense in the refactored-note template, since it's the one place the extracted body is available to insert. The destination and filename-prefix templates realistically only need {{date:…}} and {{title}}, but all six are recognized wherever a template field appears.

Unknown tokens render as nothing

A token Minerva doesn't recognize — a typo, or one borrowed from the wrong field — quietly resolves to an empty string rather than raising an error or leaving the literal {{…}} in the output. That keeps a mistyped token from leaking brace characters into a filename, but it also means a silently-wrong template just produces a slightly-off result with no warning. The one template with a real failure mode is the refactored-note template: it wraps the extracted body wherever {{new_note_content}} appears, so a template that omits that token entirely discards the extracted content — the new note is created from the template text alone, with nothing to show for the selection you just extracted.

Excerpt notes

A single setting, separate from Refactoring because it's stored differently: this one is per-project, not per-machine.

Default destination folder
Text field, placeholder "(project root)". The project-relative folder where New note from excerpt lands. Leave it blank and excerpts land at the thoughtbase root; the folder is created automatically on the first write if it doesn't already exist.
Where this lives on disk

Unlike the Refactoring settings above, the excerpt destination folder is stored in the project itself, at .minerva/config.json, under an excerpt.noteFolder key. That makes it a project convention rather than a personal one — it travels with the project if you sync or git-track .minerva/, the same way bookmarks do. It's telling Minerva where excerpts belong within this project's structure, not expressing a personal habit the way the Refactoring defaults do.
