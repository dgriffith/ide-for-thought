Scopes & privacy

Every exporter shares the same two questions underneath: what counts as "in scope," and what gets held back even though it's technically in scope. Both are settled before you commit to running anything — the export preview shows you exactly what you're about to get.

Scope

Single note
Just the active note.
Folder
A folder and everything under it, recursively.
Project
The whole thoughtbase.
Tree
A root note's wiki-link closure — every note reachable by following links outward, breadth-first, to a max depth (default 3, to balance "capture enough context" against a runaway bundle).
Source
A single ingested source, for the Annotated Source exporter.

What's excluded by default

Minerva holds personal thinking, half-formed arguments, and reading notes — accidentally publishing those would be a real problem, so exports drop anything matching a private signal unless you explicitly override it. Three signals, checked in order:

1. Location
The note's path is under any private/ or .private/ folder.
2. Frontmatter
private: true.
3. Tag
#private — either in a tags: frontmatter array or inline in the body.

Every exclusion comes with a human-readable reason ("under private/", "frontmatter private: true", "tagged #private") — nothing is dropped silently.

Reviewing before you export

The export preview shows two lists: what's included, and what's excluded along with its reason. From there:

Re-include an excluded note
Click its row in the Excluded list — an override just for this run, not a permanent change to the note.
Drop an included note
Uncheck it in the Included list — it moves to Excluded with the reason "manually excluded," again just for this run.
