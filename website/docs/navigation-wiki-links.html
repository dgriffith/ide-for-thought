Wiki-links

A [[Note Name]] link is clickable wherever it's rendered. This page covers the navigation experience — following a link, previewing its target on hover, and what happens when the target doesn't exist — not the link syntax itself. For the [[type::target#anchor|display]] grammar, the twelve typed-link types, and resolution priority, see Links.

Following a link

The click gesture depends on which pane you're in — preview has no "edit the link text" concern, so it can afford a plain click where the source editor can't:

Preview
A plain click on a rendered [[...]] link follows it — no modifier key needed. There's nothing to edit in rendered output, so a click can't be ambiguous with placing a cursor.
Source editor
A plain click follows the link, same as preview. ⌘-click (or Ctrl-click) instead places the cursor inside it, so you can edit the target or display text — the same convention the editor uses for footnotes. See Links.
Hover
Hovering a link (in preview) shows a popover with the target note's title and its opening snippet, without navigating. See below.
Unresolved target
Clicking a link whose target doesn't match any note does nothing visible — no new note is created, and no error dialog appears. See Gotchas.

Both contexts resolve the target through the same resolver used for graph indexing — a link goes to the same place whether you click it in preview, in source, or reach it from the Backlinks panel. See how a target resolves for the exact match order.

Hover preview

Hovering a wiki-link in preview — without clicking — opens a small popover showing the target note's title and a truncated opening excerpt (or the relevant heading/block section, if the link has an anchor). It's read-only: moving the pointer away dismisses it, and nothing about the current note or the target changes. The read is cached briefly per path so re-hovering the same link doesn't refetch it every time.

If the target doesn't resolve to any note, the popover shows a quiet "target" not found line instead of an excerpt — this is the only place the navigation UI distinguishes a resolved link from an unresolved one. See Gotchas.

Links and the knowledge graph

Every wiki-link is indexed on save as a triple from the source note to its resolved target, regardless of whether you ever click it — following a link and indexing it are independent of each other. The link's type (or references, untyped) becomes the triple's predicate, which is what powers the right sidebar's Backlinks panel and SPARQL queries over the graph. Clicking to navigate doesn't write anything; it only reads the already-indexed resolution. See Backlinks.

Gotchas

  • An unresolved link does not create the note. Clicking a [[...]] link whose target doesn't match any existing note does not create a new note and does not show an error dialog — the click is silently a no-op. Under the hood, navigation resolves the target and, on no match, falls back to treating it as a literal target.md path; opening that path reads the file from disk, which rejects because the file doesn't exist, and nothing catches that rejection. No tab opens, nothing changes on screen. If you're expecting a link to work and it doesn't, check the Backlinks panel or a graph query to see how the target actually resolved.
  • Unresolved links look identical to resolved ones. There's no distinct color or underline style for a link that doesn't resolve — the only tell in the UI is the hover popover's "target" not found line, covered above.
  • Preview and source editor agree on the click gesture only up to a point. Both follow a link on plain click; only the source editor treats ⌘/Ctrl-click specially (to place the cursor for editing). Preview has no modifier behavior to speak of — a modified click still just follows the link.
