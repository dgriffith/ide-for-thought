Docs/Query/Result blocks

Result blocks

Instead of a static export, a query's results can live in a note as a block that re-runs every time the note renders — a list, a table, or a chart. The Query panel's "Copy as…" dropdown generates these for you (see Query menu & panel), or you can write one by hand.

Lists & tables

:::query-list and :::query-table wrap a query with a small YAML-ish config header, then render its results live:

columns
Restrict and order which result columns actually show. Omit it to show every column the query returns.
link
Which column, if any, should navigate to a note when clicked. Defaults to a column named path.

Table results are sortable in preview the same way the Query panel's results are — click a column header to toggle ascending/descending.

Timeseries charts

:::query-timeseries renders numeric results as a chart instead of a table:

x
The column to use as the x-axis.
y
One or more columns to plot, comma-separated.
type
line, bar, or area.
height
Chart height in pixels.
title
A title shown above the chart.
Example

:::query-timeseries
x: month
y: revenue, cost
type: area
---
SELECT date_trunc('month', date) AS month, SUM(revenue) AS revenue, SUM(cost) AS cost FROM sales GROUP BY month ORDER BY month;
:::

Discovering a table's schema first

Before you write a query against a CSV-backed table, it helps to know its actual column names. Two stock SQL queries do this without you needing to remember DuckDB's syntax: Describe schema (DESCRIBE your_table;) and Summarize (SUMMARIZE your_table;, which adds per-column stats). The Query panel's SQL autocomplete also surfaces real column names as you type, once a table is registered.
