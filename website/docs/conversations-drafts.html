Docs/Conversations/Drafts

Drafts

A draft card is what the AI hands back instead of writing anything: a not-yet-submitted candidate — a note, a set of tags, a claim, a rewrite — sitting inline in the conversation transcript, waiting for you to accept it or throw it away. Nothing it describes exists in your project until you say so.

When a draft card appears

A draft card shows up whenever a conversation tool produces something that would change your project. Ask the AI to file a new note and you get a note draft; ask it to summarize a source, tag a batch of files, extract claims from a paper, rename or reorganize notes, rewrite a note body, or generate a runnable code cell, and you get the matching card type — DraftCard, ComputeDraftCard, RefactorDraftCard, ReorgDraftCard, DeleteDraftCard, or NoteBodyDraftCard (src/renderer/lib/components/conversations/DraftCards.svelte). Each card is anchored to the assistant turn that produced it and renders directly under that message — you don't have to go looking for it in a separate panel.

Accept
Files the draft exactly as shown. Labeled per card type — "Approve & file" for notes, "Approve & ingest" for sources, "Approve & apply" for property/tag patches — and replaces the card with a compact, persistent "Filed:" line linking to whatever landed.
Edit
Only the compute-cell draft is actually editable before it runs: ComputeDraftCard keeps its own edit buffer, and Run/Insert send your edited code (falling back to the AI's original if you didn't touch it) rather than the draft's stored text. Every other draft type — note, source, property, source-property, claims, refactor, reorg, delete, note-body rewrite — has no in-card editing. You're deciding on exactly what the AI produced.
Discard
Drops the card from the conversation's draft list with no further action — no proposal is ever created, nothing is written, and there's no undo beyond asking the AI to try again.
Draft vs. proposal

A draft only exists in the renderer's conversation state — it's never touched the knowledge graph. A proposal is a thought:Proposal node the approval engine has actually written to .minerva/graph.ttl. Clicking Accept on a draft card is the moment one becomes the other: the main process calls approval.proposeWrite() to file the proposal, then immediately calls approval.approveProposal() on it, because you already made the accept/discard call at the card — a second pending state in the Proposals panel would just be busywork. Every draft type resolves this way (src/main/ipc/register-conversation.ts, e.g. the note-draft handler at CONVERSATION_FILE_DRAFT: propose, then approve, in the same handler), so the trust principle still holds — the write still goes through the approval engine, it just doesn't linger in a pending state you have to separately clear. For the mechanics of reviewing a proposal that isn't auto-approved this way — the diff view, the Approve/Reject keystrokes, the tier table — see The propose → review → approve loop and Proposals.

Gotchas

  • "Accept" doesn't mean "unreviewed." Because Accept immediately approves the resulting proposal, a filed draft won't show up under the Proposals panel's Pending tab — it lands directly in Approved, same as a notify_only-tier write. If you want a record of what an AI conversation has filed, look under Approved, not Pending.
  • Discarding is final, not a rejection record. Unlike rejecting a proposal in the Proposals panel — which keeps a rejected node in the graph as an audit trail — discarding a draft card never created a graph node to begin with, so there's nothing left behind to show the AI once suggested it.
  • The compute draft's "edit" is a local buffer, not a re-prompt. Editing the code in a compute card changes only what gets executed or inserted; it doesn't send your edit back to the model or change the conversation transcript. If you want the AI to reconsider its approach, ask again rather than relying on your edit to inform its next turn.
  • Refactor, reorg, and delete drafts can be partial. ReorgDraftCard and DeleteDraftCard let you select a subset of the proposed items before accepting — accept only applies to what's checked, the rest of the card's suggestions are silently dropped, not held over as a smaller draft.
