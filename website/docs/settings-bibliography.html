Bibliography

The Bibliography tab in Settings picks the CSL (Citation Style Language) style Minerva renders your bibliography in, and lets you import additional styles or locales beyond the bundled set. It's the only setting behind Refactor → Insert/Update Bibliography — there's no separate citation formatting anywhere else, and no live connection to a reference manager. Bringing in an existing library — Zotero, BibTeX, or otherwise — is a one-time file import from the Sources panel, covered in Left sidebar → Sources, along with the [[cite::id]] / [[quote::id]] link syntax that actually produces a citation.

Settings

Citation style
Dropdown. Default APA (7th edition). Choose from six bundled CSL styles — APA, MLA (9th edition), Chicago (author–date), Chicago (notes & bibliography), IEEE, and Vancouver (NLM citation-sequence) — plus anything you've imported yourself (labeled "(imported)" in the list). Stored per-project in .minerva/config.json, so different thoughtbases can follow different style guides. This is the style Refactor → Insert/Update Bibliography renders with; there's no per-note override.
Imported styles
Drop a .csl file into .minerva/csl-styles/, or use the Import .csl style… button to pick one with a file dialog. Either way it shows up in the Citation style dropdown above (and in the export dialog's style picker) immediately — no restart. Each imported style is listed here with a Remove action. The Zotero Style Repository publishes 10,000+ open CSL styles if the bundled six don't match what you need.
Imported locales
Optional. The only bundled locale is en-US — it supplies the translated terms citeproc renders into a citation or bibliography entry (things like "and", "ed.", "no date", month names), not sort order, which each CSL style defines on its own. Import a CSL locale XML file via Import locale .xml… to render in another language; official locales live at github.com/citation-style-language/locales. Imported locales land in .minerva/csl-locales/ and are listed here with a Remove action. There's no picker to select which locale is active — Minerva always renders with en-US unless you're using a style that hardcodes a different one internally.

This tab formats citations — it doesn't create them

Nothing here writes a citation into a note. You cite a source with [[cite::sourceId]] or quote a saved excerpt with [[quote::excerptId]] in the note body, then run Refactor → Insert/Update Bibliography to scan the note for those links and render a ## References section in the style configured on this tab. Re-running it is idempotent — it replaces its own previously-rendered block (tracked by an HTML comment pair) without disturbing any prose you've added around it, so it's safe to run again after adding more citations.

Gotchas

  • Styles and locales live in separate directories. An imported .csl file goes in .minerva/csl-styles/; an imported locale XML goes in .minerva/csl-locales/ — dropping one in the other's folder means it's silently never picked up.
  • The style choice is per-project, not global. Switching thoughtbases can mean switching bibliography styles too — check this tab if a freshly-opened project's References section renders differently than you expected.
  • An imported style or locale with the same id as a bundled one wins. Project files always take precedence over the bundled set on a filename collision, so you can override, say, apa.csl with your own variant without touching app source — but it also means a badly-named import can silently shadow a built-in style.
  • No live reference-manager connection. There's no Zotero or Mendeley account to sign into here — building up a library happens once, via File → Import BibTeX… / Import Zotero RDF… or one-at-a-time ingest in the Sources panel. See Left sidebar → Sources for those flows.
  • A cited id citeproc can't resolve doesn't block the rest. Insert/Update Bibliography still renders every entry it can; unresolved ids are surfaced separately rather than failing the whole command.
