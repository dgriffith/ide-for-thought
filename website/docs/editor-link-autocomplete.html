Link autocomplete

Typing [[ opens a suggestion list of notes and aliases, filtered as you keep typing. It saves you from remembering exact filenames — and from a typo quietly producing a link to nowhere. This page covers the trigger, the filtering, and — verified directly against the completion source, not assumed — exactly what happens when nothing matches.

Triggering the list

The popup isn't tied to the single act of typing [[ — it re-evaluates on every keystroke while your cursor sits inside an unclosed pair. Start a link, and the list stays open and refiltering as you type, narrows and reorders as you add characters, and disappears once you type the closing ]] or leave the link.

Trigger
Typing [[ anywhere in a note opens the list. It stays live on every subsequent keystroke as long as the cursor is inside an open pair — there's no separate "re-trigger" gesture, it's continuous.
Filter
Whatever you type after [[ narrows the list. Filtering is CodeMirror's built-in fuzzy matcher — a subsequence match, case-insensitive — not a Minerva-specific search, so out-of-order characters can still match (e.g. mtg can match Meeting Notes).
Select
Arrow keys move through the list; clicking an entry also works. Esc dismisses the popup without changing anything you've typed.
Accept
Tab or Enter accepts the highlighted entry, inserting its title or alias in place of what you'd typed so far. Accepting never inserts brackets — you already typed [[, and Minerva doesn't auto-close ]] for you.
No match
If nothing in your notes matches, the list shows no items — there's no "Create new note" entry. See Gotchas for the verified detail.

The list draws from two sources at once: every note's path (title, effectively) and any aliases: frontmatter entries across the project, so an alias you've defined is just as reachable as the note's real filename. A note path ranks slightly above a matching alias when both match the same typed text, so the canonical name wins ties. Typing type:: first (e.g. supports::) also offers the twelve link types as completions before you get to the target text, and cite:: switches the whole list over to your indexed sources instead of notes.

Gotchas

  • Typing text that matches no note does not create anything — the list is simply empty. The completion source builds its option list strictly from existing note paths, aliases, headings, block ids, or sources, depending on which part of the link you're typing — there's no branch anywhere that synthesizes a "create new note" option from your typed text. If you finish typing a target that matches nothing and close the brackets yourself, you're left with a plain unresolved [[...]] link, exactly as if you'd typed it without ever seeing a suggestion. This mirrors the click-navigation behavior documented in Navigation → Wiki-links — an unresolved target is a quiet no-op there too, not an auto-create — so the two code paths agree even though they're independent.
  • Closing the brackets yourself has no special effect. Autocomplete is purely an insert-before-you-finish-typing convenience. Typing the closing ]] just ends the phase the popup was tracking; nothing is validated, created, or written at that moment.
  • Accepting mid-word eats the leftover tail, not just what's before the cursor. If you're editing inside an existing link — say the cursor sits in the middle of [[No|te]] — accepting a suggestion also removes the contiguous run of word characters right after the cursor, so you get a clean [[Notebook]] instead of [[Notebooknote]]. It stops at the first non-word character, so it won't reach past a ] or a ,.
  • The popup closes at |. Once you type the display-text separator, completion stops offering target suggestions — everything after | is free text, same as writing [[target|display]] by hand. See Links → Syntax.
