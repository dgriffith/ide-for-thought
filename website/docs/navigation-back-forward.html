Back / forward

Minerva keeps a position history as you move between notes, sources, and query tabs — ⌘[ steps back, ⌘] steps forward (Ctrl on Windows/Linux), and the same two arrows sit in the title bar. It behaves like a browser history stack, with one distinction worth knowing: not every way of landing on a note counts as a step in that history.

Controls

⌘[
Back. Returns to the previous recorded position. Disabled (and the toolbar button greyed out) when there's nothing behind you.
⌘]
Forward. Re-applies a position you just came back from. Disabled once the forward stack is empty.
Toolbar arrows
Two buttons at the left edge of the title bar, before the breadcrumb — the same back/forward affordance as a browser's, wired to the same shortcuts. Each is disabled exactly when its shortcut would be a no-op.

A position isn't just a note — it's a note and a place in it. Going back returns you to the same scroll/cursor offset you were at, not just the top of the file. Query tabs and source views are tracked in the same stack, so stepping back out of a SPARQL query or a source detail view works the same way.

What counts as a step

Every navigation records the position you're leaving before it moves you — so the history stack is really a trail of where you've been, not where you're going. The open question for any given way of jumping to a note is whether it leaves a trail at all:

Sidebar click
Recorded. Selecting a note in the left sidebar tree records the position you left and the one you land on.
Wiki-link click
Recorded. Following [[a link]] in preview or source pushes a history entry, same as a sidebar click — link-hopping through a chain of notes builds a full trail you can walk back out of.
Quick switch (⌘P)
Recorded. Jumping to a note, source, or saved query from the Quick Switch palette records a step, the same as clicking it in the sidebar would.
Find in Notes result
Not recorded. Jumping to a match from Find in Notes opens the file and moves the cursor directly — it doesn't push a history entry. Back skips over these jumps entirely.
Back / forward itself
Moving through the stack doesn't add to it — stepping back and forward repeatedly doesn't grow the trail or create duplicate entries.
A fresh navigation clears what's ahead

Step back a few notes, then click a wiki-link or open something new from the sidebar — the forward stack is discarded at that point, exactly like a browser tab. The notes you stepped back past aren't gone from history in general, but the specific "forward" path to them is; you'd have to navigate to them again to revisit them.

A few more details

  • History is capped. The back stack holds at most 100 entries; once full, the oldest position is dropped as a new one is added.
  • Repeat visits don't duplicate. Recording a position that's effectively the same as the one you're already on — same note, cursor within roughly 20 characters, or the same query tab — is skipped rather than pushed as a new step.
  • History doesn't survive a project switch. Opening a different thoughtbase starts a fresh, empty stack.
