Footnotes

Footnotes let you push an aside, a caveat, or a citation-adjacent remark out of the sentence and down to the bottom of the note. You write a small inline marker where the thought occurs and a matching definition anywhere in the file — Minerva keeps the two connected in every view: rendered preview, source editor, and the right-sidebar Footnotes panel.

Syntax

Minerva uses the standard Pandoc-style footnote extension to markdown: a reference marks the spot in your text, and a definition supplies the footnote body.

[^label]
Reference. Placed inline in body text. The label can be a number ([^1]) or a name ([^caveat]) — letters, digits, underscores, and hyphens; no spaces.
[^label]: text…
Definition. Must start at the beginning of a line — column zero, no indent. Conventionally these collect at the bottom of the note, but a definition anywhere in the file works.
indented lines
Continuation. A multi-paragraph footnote continues on indented lines below the definition. A blank line is fine mid-definition as long as the next non-blank line is still indented; the first unindented line of text ends the footnote.
\[^label]
Escape. A backslash before the bracket makes it literal text, not a footnote. References inside code fences and inline `code` spans are also ignored.

A complete example:

The results replicate the 2019 study,[^rep] though with a smaller
effect size.[^size]

[^rep]: Only the primary outcome was replicated; the secondary
    measures did not reach significance.

[^size]: d = 0.31 vs. the original d = 0.62.

How footnotes render

In preview, each reference becomes a numbered superscript link, and all the definitions gather into a footnotes section at the bottom of the rendered note. Clicking a superscript smooth-scrolls to the footnote body and briefly highlights it so your eye lands in the right place; each body ends with a return arrow that jumps back to the reference. You don't have to jump at all, though — hovering over a superscript shows the footnote text in a tooltip right where you are.

Labels vs. numbers

The label is an identifier, not the displayed number. Rendered footnotes are numbered by the order their references appear in the text — [^caveat] renders as ¹ if it's the first footnote referenced. Use descriptive labels freely; the output stays tidy.

In the source editor

In source view, footnote references and definition openers are highlighted as links. They navigate in both directions:

  • Click a reference — jump to its definition.
  • Click a definition — jump to the first place it's referenced.
  • ⌘-click (or Ctrl-click) — place the cursor inside the marker to edit it, without jumping. Same convention as wiki-links.
  • Hover a reference — a tooltip previews the definition body, so you can read the footnote without leaving the sentence. If the label has no definition yet, the tooltip says so.

To insert a footnote, run Insert Footnote from the command palette: it drops the next free numbered reference ([^1], [^2], …) at the cursor, appends the matching definition at the end of the note, and moves the cursor there so you can type the body immediately. You can bind it to a keyboard shortcut in Settings → Editor.

The Footnotes panel

The right sidebar's Footnotes panel lists every footnote in the current note in source order, with a preview of each body and a search box for longer notes. Clicking an entry scrolls the editor to the footnote's first in-text use. The panel also doubles as a linter — it flags the two ways footnotes go stale:

  • Defined · never used — a definition no reference points at (shown muted).
  • Referenced · not defined — a [^label] in the text with no matching definition. Clicking it takes you to the dangling reference so you can write the missing body.

Gotchas

  • Duplicate labels. Define each label once. If two definitions share a label, hover previews and click-to-jump resolve to the first one, and the second silently loses.
  • Reusing a reference is fine. The same [^label] can appear several times in the text, all pointing at one definition. Clicking the definition jumps to the first use; the Footnotes panel does the same.
  • Definitions must start at column zero. An indented [^label]: line isn't a new definition — it reads as a continuation of the footnote above it (or as plain text).
  • Punctuation placement. The convention is marker after punctuation: word.[^1], not word[^1]. The formatter's Footnote reference after punctuation rule fixes this automatically when you format a note.
