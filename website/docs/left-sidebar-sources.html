Sources

The Sources tab (labeled sites internally, rendered by SourcesPanel.svelte) is Minerva's reference manager: a captured web page, PDF, or bibliography entry, with its own metadata, a markdown body, and excerpts you can cite from your notes. It sits alongside the notes tree as a second first-class content type — not a bookmark list, a working bibliography.

What a source is

A source is metadata plus an extracted body, stored as plain files at .minerva/sources/<sourceId>/ — never inside your notes tree. Each source directory holds meta.ttl (Turtle metadata: title, creators, year, publisher, DOI, tags, and more), body.md (the extracted content, rendered and editable the same way a note is), and, when the original was a web page or PDF, original.html or original.pdf alongside it for re-extraction or offline reference. The source id itself is derived from content or identifier — a URL hash, a DOI, a file hash — never a human-readable slug, which is why every row and header shows a computed display title rather than the id.

Source vs. note

A source is not a note with different frontmatter — it's a distinct RDF class (thought:Source, with subtypes like thought:WebPage, thought:Article, and thought:PDFSource) living outside the notebase file tree. You can still write a note about a source — the source detail view has a "New note about this source" action that pre-fills about: [[sources/<id>]] frontmatter — but the source's own body and metadata are edited from the Sources panel, not the notes tree.

Browsing the panel

The panel stacks three sections above the flat source list, each acting as a filter scope:

Collections
A nested, expandable tree of manual collections (you assign sources to them by hand) and smart collections — saved queries that populate automatically from a predicate you define. Each row shows a live member count. Selecting a collection scopes the list below to its members.
Reading queue
A collapsible section with four built-in views — Unread, Reading, Due this week, and Recently finished — each with a live count, driven by the per-source read status and due date rather than anything you curate manually.
Filter field
A single text box above the list. It matches against the displayed title, the byline (creators), the year, and the source id — whichever collection or queue view is currently selected. There's no separate sort control; order comes from however the backend returns the list.

Each row in the flat list (SourceListItem.svelte) shows:

Title
The computed display title — the real dc:title if one was extracted, otherwise a cleaned-up form of the source URL. Rendered in the same italic display face used for citations.
Status dot
A small glyph next to the title if a reading status is set (unread / reading / read / skipped) — absent for sources with no status.
Byline
Creators, then year, then a due-date stamp if one is set — whichever of those three are present, joined with a middle dot. An overdue due date is styled distinctly from one still upcoming.

There's no favicon or domain column — this is a bibliography list, not a browser-style bookmark manager. Clicking a row opens the source's detail view in a tab, the same way clicking a note opens it in the editor. Right-clicking gives you rename, add tag, add/remove collection membership, set reading status or due date, copy DOI, mine references, merge into another source, and delete.

Getting sources in

Nothing is captured automatically — every source starts from an explicit action:

Panel "+" button
Next to the filter field. Prompts for a URL, DOI, arXiv id, or PubMed id and figures out which it is, then ingests it. The fastest path when you're already looking at the panel.
File → Ingest URL as Source… ⌘⇧I
Fetches the page, runs Mozilla Readability to extract the article content, and converts it to markdown. Re-running this on a URL you've already ingested merges any newly-found metadata into the existing meta.ttl without touching your edited body.md.
File → Ingest Identifier… ⌘⇧D
Looks up a DOI, arXiv id, or PubMed id and pulls structured bibliographic metadata, fetching an open-access PDF where one exists.
File → Ingest File as Source…
Local-file picker. PDFs go through text-layer extraction (or a two-step OCR flow if the PDF has no text layer); HTML files go through the same Readability path as a URL; plain markdown/text files are stored verbatim.
File → Import BibTeX… / Import Zotero RDF…
Bulk import from an existing bibliography export — for bringing an established reference library into a project in one pass rather than one source at a time.
Browser clipper
A companion browser extension pairs with Minerva over a local, secret-gated loopback connection (paired and rotated from Settings → Browser Clipper) and sends the current page straight into the same ingest pipeline — for capturing while you're reading in the browser, without switching to the app first.
Ingest needs the network

URL, identifier, and clipper capture all fetch live over the network — there's no offline queue that retries later. Local-file ingest is the only path that works without a connection. There's also no "refresh" action on an existing source: re-ingesting a URL merges fresh metadata but leaves the body alone, specifically so edits you've made to body.md survive.

Opening a source

Clicking a row opens SourceDetail.svelte in a tab — the same tab strip a note uses. The header shows the subtype (Article, Web Page, PDF, and so on — with a "STUB" marker for a reference-mined placeholder that hasn't been resolved yet), the title, the byline, and editable tag chips. Below that, a metadata block lists whatever fields are present — Publisher, DOI (a clickable external link), URL, the raw source id, reading-status buttons (Unread / Reading / Read / Skipped — click the active one again to clear it), and a due-date picker. Action buttons cover Open original PDF (when one was captured), Rename source, and Delete source.

If the source has an abstract, it renders above the body. The body itself — body.md — renders through the same markdown preview a note uses, and has its own Edit body toggle that swaps in a plain-text editor for direct changes. Selecting text inside the rendered body opens a small context menu to save it as an excerpt — a separately stored, precisely anchored quotation you can later cite by id. A density gutter along the body's scrollbar marks where existing excerpts fall. Further down, a References section lists any sources this one cites (including unresolved stubs created by reference-mining), and a "Referenced from" section lists notes that cite or quote this source — both clickable.

Deletion has no undo dialog trapdoor — it has git

Deleting a source removes its excerpts and its entire .minerva/sources/<id>/ directory in one pass. The confirmation reads plainly — "Delete source "name"? Any excerpts from this source will also be removed." — with no red styling and a "don't ask again" option, same as deleting a note. Wiki-links or cite/quote links pointing at the deleted source become dead links; recovery is what git is for.

Sources, notes, and citations

A source is cited from a note using the typed wiki-link syntax, not through any UI in this panel: [[cite::sourceId]] points at a source as a bibliography-style reference, and [[quote::excerptId]] points at a specific excerpt for a direct quotation. Both are indexed into the graph the same way any typed link is, which is what powers the "Referenced from" list on the detail view above. See Notes → Links for the full typed-link mechanics and how targets resolve — this page covers the panel you browse and capture sources from, not the citation syntax itself.

Gotchas

  • No favicon, no domain, no browser-bookmark styling. The row and header UI are built around bibliographic fields (creators, year, publisher, DOI) — if what you want is a lightweight bookmark list, see Bookmarks instead.
  • Renaming a source only changes its title, not its id. Rename source upserts dc:title in meta.ttl; the on-disk directory and the id any citations resolve against stay exactly as they were.
  • Encrypted PDFs are rejected outright during ingest, with a clean error rather than a partial/garbled capture.
  • Scanned PDFs need an OCR step before they have a body. A PDF with no text layer ingests immediately (metadata and original.pdf are saved), but body.md stays empty until you run — or explicitly skip — the OCR pass Minerva offers.
  • Merging two sources is manual and irreversible on the losing side. The merge picker warns that excerpts and citations of the source being merged away move to the target, then the original is removed.
