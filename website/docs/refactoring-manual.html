Manual rename, move & delete

Doing it yourself, right in the Notes tree — and what Minerva keeps consistent for you when you do.

Right-click and drag

Rename
Right-click a note → Rename. Also reachable from the command palette as Rename Note… (no default keyboard shortcut).
Move
Drag a note onto a destination folder, or use the command palette's Move Note… (also no default shortcut) to type a destination path instead.
Delete
Right-click → Delete. See Safe delete & dangling links for what happens before it actually deletes anything.
Cut / Copy / Paste
Standard clipboard operations are also available from the right-click menu, as another way to move or duplicate notes between folders.

What auto-updates

Rename or move a note, and Minerva rewrites references to it across the rest of the thoughtbase:

Wiki-links
[[old]] becomes [[new]] everywhere it's referenced — preserving a type prefix ([[type::old]] → [[type::new]]), display text ([[old|label]] → [[new|label]]), and an anchor ([[old#heading]] → [[new#heading]]).
Relative markdown links & images
A plain [text](path) or ![alt](pic.png) gets re-relativized both from the moved note's new location, and from any other note that links to it — so a relative path stays correct on both ends of the link.

What does not update: source and excerpt citation markers ([[cite::id]], [[quote::id]]) — those target a stable id, not a path, so they're unaffected by a note moving in the first place.

Folder renames work, but differently

Renaming a whole folder works via drag-and-drop, the same as moving one — there's just no dedicated prompt-driven shortcut for it the way single-note rename has one.
