Citing sources & duplicates

Once a source is ingested, referencing it from a note is a typed link, same as linking to another note — and re-ingesting the same source again is designed to be harmless.

Citing what you brought in

Write [[cite::sourceId]] to cite a source, or [[quote::excerptId]] to cite a specific excerpt — the same typed-link syntax used for linking notes to each other. The Citations panel in the right sidebar rolls these up per note: one row per source, with cite/quote counts and — for quotes — the specific passage and its locator.

Duplicate detection

Every source's id is derived from its most stable identifier (DOI, arXiv id, PubMed id, ISBN, or a hash of its URL or content — see Adding sources), so ingesting the same paper twice by the same route produces the same id every time. That turns dedup into a simple existence check: if a source folder for that id already exists, nothing gets overwritten.

Body untouched
If you've hand-edited a source's body.md since it was ingested, re-ingesting the same id leaves your edits alone.
Metadata merged, not overwritten
If the second ingest turns up metadata the first one didn't have (say, an upstream tag or a field CrossRef fills in), it's added into the existing meta.ttl rather than replacing it.
You're told, not left guessing
Re-ingesting a source you already have opens the existing source and says so plainly: "Already ingested: '<title>'. Opened the existing source."
The one real gap: different identifiers, same paper

If the same paper reaches you two different ways before either has been cross-referenced — an arXiv URL today, its DOI next month — Minerva has no way to know they're the same thing, since the two ids are computed independently. They land as two separate source folders. The fix is a manual one: right-click a source in the Sources panel and choose Merge into…, pick the other entry, and confirm — its excerpts and citations move over, and the duplicate is removed. Not automatic, but a couple of clicks once you notice it.
